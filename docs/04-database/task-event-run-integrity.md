# T032固定运行与任务事件约束

本批只补任务事件的存储完整性，依据[T032任务卡](../../tasks/backend/T032.md)、[T031候选计划解析](../03-development/t031-candidate-task-plan.md)和[现有状态词汇](../05-workflows/task-state-machine.md)。实际验证结果见[专项回执](../00-project/validation/t032-task-event-integrity-report.json)。它不实现任务创建、通用状态转移、节点聚合或真实调度。

## 0015的具体变化

[0015增量迁移](../../backend/business_migrations/0015_task_event_run_integrity.sql)在既有`task_event`上增加三条约束：

| 约束 | 必须满足的条件 | 不代表的能力 |
| --- | --- | --- |
| `task_event_run_identity_fk` | `(case_id,task_id,run_version)`必须共同指向`task_run`的同一条运行记录 | 一个案件内另一个任务的运行版本不能借用；运行存在也不证明调用者有权访问 |
| `task_event_from_state_check` | 可为空；非空时只能使用现有11种任务状态 | 空值保留创建事件的结构能力；不是任意事件免校验的业务批准 |
| `task_event_to_state_check` | 必须使用现有11种任务状态 | 状态名称合法不等于该前后状态组合合法 |

11种值完整保留：`CREATED`、`QUEUED`、`RUNNING`、`WAIT_REVIEW`、`REVIEWING`、`SUCCEEDED`、`FAILED`、`RETURNED`、`CANCEL_REQUESTED`、`CANCELLED`、`ARCHIVED`。不把节点的`READY`或候选图分支的`NOT_SELECTED`加入任务状态。没有新表或新列；完整迁移结构仍为64业务表、861字段，原62表825字段设计字典继续单独追溯。

0001—0014历史迁移及摘要保持不变；不改[原初始化设计](initial-schema.sql)冒充升级方案。本增量与原字典`task_event`各字段的语义对应：运行号由新的复合外键固定，前后状态由新增CHECK限制。公共OpenAPI和生成类型没有变化。

## 升级、失败和恢复

迁移先增加`NOT VALID`约束，再在同一迁移事务中逐项`VALIDATE`。最终成功的约束全部为已验证状态；这不是保留脏历史的免检部署。既有迁移执行器将约束变更与`mt_meta.schema_migrations`记录一起提交，并检查历史文件摘要。

合法历史升级后原任务、运行、事件的全部列值和时间不变，重复执行无操作。若发现无对应运行、未知状态或迁移末尾执行失败，整个0015回滚；0001—0014台账、原数据、权限、RLS、函数及原约束保持不变。不得自动改写不可变事件、删除历史或编造运行来使升级通过。

遇到异常历史时，先保留失败记录并核对真实来源，另形成可审阅的前向修复与恢复方案；本批不提供可破坏历史的自动修复。共享环境实施前还需真实备份、恢复核验、维护时段及采用决定。不得用移除约束的方式将旧写入行为视为安全回退。

## 验证及未完成项

测试只在新建随机隔离PostgreSQL16数据库进行：正确运行和全部现有状态词汇、错误运行/任务/案件/单位、非法状态、运行与事件的追加写保护，以及合法历史升级和三类异常历史/注入失败的原子回滚。现有取消、租约、工作权限、数据范围及令牌恢复测试配套执行；具体命令、数量和失败记录以专项回执为准。

T032仍缺完整任务创建访问层、全部升级/前向修复场景、生产迁移、实际恢复及容量验收；实际负责人和复核人未确认。T033仍缺全状态机与节点聚合。现有`Execution.transition`专用于取消事件，不能直接当通用状态事件发布器。候选DAG解析通过不代替受信场景/模块/策略映射；缺真实提供者继续拒绝。Python候选、算法继续暂缓；本轮源码同步不升级服务或共享数据库。
