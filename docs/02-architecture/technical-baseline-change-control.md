# 技术基线评审与变更控制

开发基线标识1.0-py310-cpu，DEVELOPMENT_VALIDATED；正式业务/生产状态NOT_FROZEN。依据当前用户要求执行研发工程；原件、源任务与正式审批记录不被覆盖。开发快照Git提交不是正式软件准入或验收签字。

变更记录至少包括：原因、替代的ADR/版本、影响的接口/Schema/SQL/模型/索引/数据集、依赖和许可、迁移/恢复、验证命令与实测报告、适用环境、执行人与正式批准状态。锁/镜像/权重变更后应重新执行对应门禁，不复用旧报告冒充新版本通过。

涉及生产或正式证据时，补齐实际负责人与授权、适用安全规则、软件准入和有效评审；当前Q事项未解决的范围仍保留。一般可逆研发修改按会话授权继续，不因没有正式生产批准而一概停止工程。

回退：保留旧Git快照、依赖锁、镜像ID及卷/权重摘要；应用源回退不自动回退数据库或数据。数据库升级新增迁移，执行前验证兼容及备份/恢复；不得对既有库直接执行初始DDL或默认删除卷。

正式冻结交付需包含签署/认可的决定、已核验生产环境、受支持依赖、正式模型/数据与安全性能证据，再创建具有明确批准意义的版本标签。本轮不创建“已批准生产基线”标签。
