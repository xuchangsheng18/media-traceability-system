# TB-ADR-013 开发迁移、事件与租约写回

状态accepted-development；2026-10-12；正式生产未批准。补充TB-ADR-003/005/011，不抹去1.0验证记录。

问题：IF NOT EXISTS不能证明升级，旧执行者可能在新领取后覆盖结果，UUID命令缺版本/追踪。选择：独立poc迁移账本/事务锁/源摘要，新增0002；JSON Schema唯一源事件；条件领取与lease_token/run_version/未过期条件写回；普通角色追加审计。继续使用当前PostgreSQL/Celery，不增第二套队列或重复Schema。

备选是Alembic平台、全模块事件总线及外部不可篡改审计。当前仅两个简单SQL迁移，用原生事务执行减少PoC依赖；业务长期迁移和外部审计仍须独立选择，不将本轮执行器称作完整生产迁移平台。

实测：隔离迁移与竞态15项、开发链路21项、事件7项单元；8个数据库竞争者仅一个领取，旧成功/失败均拒绝覆盖。普通角色不能更新/删除审计或改写原件引用。真实8个Celery进程、续租、取消、RLS及管理员防篡改未验证。

升级前留开发冷备；字段为新增，历史request_id只能标migration_job_id。旧UUID消息从DB取信封桥接；故障采用修复新增迁移或隔离恢复，未提供自动down迁移或旧worker回退承诺。证据与操作见[迁移手册](../../03-development/migrations-and-events.md)。
