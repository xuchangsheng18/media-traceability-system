# 数据流与一致性规划

版本：0.1；整理日期：2026-10-12；状态：规划草案，NOT_FROZEN。

授权来源登记 → 上传会话 → 隔离校验 → 只读原件及asset_id → 分析任务 → 派生媒体与算法结果 → 证据卡片 → 人工复核 → 证据包和报告。数据库事务保存任务和待发事件；发送失败可重试，消费者按事件及节点键去重。

| 存储 | 事实或数据职责 | 恢复原则 |
| --- | --- | --- |
| PostgreSQL | 授权、任务、版本、审核、对象引用及审计元数据 | 事务备份并核验恢复 |
| 对象存储 | 原件、派生媒体、证据包及报告对象 | 对象版本、摘要、保留策略单独验证 |
| 向量/全文索引 | 由已授权资产和模型版本派生 | 记录来源与版本，可重建 |
| 传播关系 | 显式事实边、带依据的推断边 | 不因连通自动推定传播或整体同源 |
| 队列/缓存 | 调度和加速 | 不作为业务审核或审计唯一事实源 |

任务租约、心跳、尝试号、检查点和条件更新用于并发恢复。队列成功不代表审核通过。对象先写后登记失败时保留可清理的孤儿记录；数据库与对象存储不是同一个事务，禁止假定跨存储原子提交。

跨案件相同字节可以按已确认策略复用底层对象，但案件来源、授权和访问记录分别保存，去重接口不能泄露其他案件是否存在该文件。访问撤销应覆盖已发凭据、缓存及Range读取；具体契约见安全专题。

正式证据更正追加版本，不覆盖历史。保留期限、WORM实施、可信时间源及备份域均待相应未决事项确认。
