## 测试夹具与断言口径

复用现有pytest、隔离PostgreSQL测试实例、业务应用工厂、版本迁移及合成身份适配器。只建立无敏感信息的独立数据库和临时目录，不写共享研发库，不启动/重启共享服务，不读取真实私钥。测试权威须检查明确的动作、用户、单位、案件、对象、用途、版本和有效期；现有TestAuthority不能证明角色权限，因为其主要校验测试令牌及案件。禁止把此夹具接入正式环境。

每个权限反例先保证请求结构、UUID、请求头、版本/幂等前置和其他授权条件正确，再只改变目标条件。允许请求作为对照，并检查拒绝后数据库、对象存储、队列/outbox、导出回执与关联结果没有新增业务成功副作用；可有按设计保存的失败审计。认证/策略故障和凭据无效分开，不用一个宽泛的“401/403/404/503任意值”断言。

401用于缺少有效凭据，须有适用Bearer challenge；已认证且缺功能权限的明确拒绝为403。按既有契约及实现隐藏越界资源时单独固定404。身份/策略/目录等依赖未配置或不可用时保持503。上述HTTP语义依据[RFC 9110 §15.5.2—15.5.5](https://www.rfc-editor.org/rfc/rfc9110.html#name-401-unauthorized)，默认拒绝及逐请求校验参考[OWASP授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。它们不替代本项目正式业务授权。

## 分组场景

| ID | 类型 | 前提与输入 | 精确预期/待落实点 |
| --- | --- | --- | --- |
| AUTH-01 | 未认证 | 身份/策略适配器健康；请求字段、UUID和其他前置有效；不带Authorization | 401；WWW-Authenticate包含Bearer；无业务数据或成功副作用 |
| AUTH-02 | 凭据格式 | 空Bearer、错误scheme、无效令牌；每次只改变一个条件 | 401；无令牌回显；与适配器故障503分别测试 |
| AUTH-03 | 令牌边界 | 失效/过期/撤销、issuer/client/audience不符、映射缺失或跨issuer复用subject | 凭据不满足时401；网络或权威故障保留503；不创建本地用户 |
| PERM-01 | 无功能权限 | 有效身份及有效单位/案件；仅移除当前操作必需权限 | 403；禁止2xx；不得因拥有案件成员或管理员角色自动放行 |
| PERM-02 | 六角色默认拒绝 | 六角色分别组合；无显式批准的功能/对象授权 | DENY；候选职责不视为允许；多角色不能覆盖来源限制 |
| PERM-03 | 最小许可对照 | 仅自建fixture明确授予该权限及适用数据范围，全部其他前置有效 | 进入预定业务路径；状态按该操作契约/夹具断言，禁止把非权限503当授权成功 |
| PERM-04 | 未知权限/漏标记 | 注册未识别权限或新受保护路由不声明权限 | 配置/路由覆盖门禁失败或请求拒绝；不得默认公开 |
| REVOKE-01 | 角色/绑定撤销 | 先完成fixture允许，再撤销user_roles/role_permissions或禁用role/permission，旧令牌再次请求 | 有效身份但功能许可已撤销返回403；不因旧会话/旧缓存保留权限 |
| REVOKE-02 | 用户/单位/映射撤销 | 禁用用户/单位或撤销身份映射，再使用原令牌 | 按现有凭据映射拒绝401；无原成功内容缓存泄漏 |
| REVOKE-03 | 到期边界 | 分别在expires_at之前、相等、之后测试角色/成员/身份；控制时钟不靠sleep | 相等即失效；按功能/身份/资源边界分别403/401/隐藏404 |
| REVOKE-04 | 策略版本/并发撤销 | 旧策略版本或检查后写入前、后台重试前撤销；依实际事务/版本方案设计屏障 | 最终受保护动作不得使用失效授权；SLA未定时标待验证，不能写虚构毫秒数 |
| SCOPE-01 | 同单位跨案件 | 用户、单位、动作权限均有效，目标案件未授权或成员撤销 | 沿既有隐藏规则404；不返回目标存在性/原文/游标；不能用403/404任意其一断言 |
| SCOPE-02 | 跨单位 | 相同角色/权限但目标资源在另一单位；篡改header/body/query的org_id | 资源型沿RLS隐藏404；单位范围操作按精确矩阵固定拒绝；不得返回对方数据 |
| SCOPE-03 | 对象及历史替换 | 替换upload/task/asset/cluster/approval/review/export等ID或history版本，保持原获准案件参数 | 对象归属从可信库解析；越界资源404；历史内容/下载/关联ID不泄漏 |
| SCOPE-04 | 列表游标与幂等重放 | 跨用户/单位/案件重用游标及幂等key，包含合法编码和篡改编码；范围撤销后重放 | 按现有签名/编码/范围错误精确断言；不可重放旧成功响应绕过新授权 |
| SOURCE-01 | 来源/用途撤销 | 已授权案件内，来源授权撤销、到期或用途不符，含上传续传/任务重试 | 沿现有来源规则403；不新增分片、任务、outbox、导出或成功回执 |
| FAULT-01 | 身份/策略故障 | 身份适配器缺失、目录超时、正式策略未配置或返回绑定不符 | 503；不得降级TestAuthority/旧权限或记录业务成功 |
| FAULT-02 | 数据库与连接复用 | 隔离数据库故障、特权连接、两主体顺序复用同一连接池 | 故障503或安全配置拒绝；事务user/org无残留；特权RLS绕过被拒 |
| PRIVACY-01 | 错误/日志隐私 | 为以上拒绝请求设置可识别但无真实敏感信息的合成标记 | Problem/日志不含令牌、密钥、跨单位对象内容、SQL堆栈；失败审计与业务成功分开 |
| SPECIAL-01 | 开发登录例外 | devLogin明确security:[]且development-only | 不按缺Bearer强求401；验证开发开关、输入和正式环境关闭边界；不扩大公开例外 |
| SPECIAL-02 | 内部服务边界 | 内部推理入口使用用户Bearer或错误服务身份/能力/案件绑定 | 按内部契约拒绝；用户角色不能替代服务身份；单列内部测试不计入73外部操作 |
| SPECIAL-03 | 健康与文档入口 | PoC健康检查、业务health.read、框架文档路径分别访问 | 分别固定公开/受保护范围；不能因healthz或PoC令牌成功断言业务角色权限已验证 |

## 逐操作与六角色参数化

机器附表逐项列出全部73个operation_id适用场景。72个受保护操作均设计未认证、无权限、默认拒绝、撤销及故障场景；六角色无显式授权的组合共432组，全部是计划数，不是通过数。案件型操作再设计同单位跨案件、对象/历史替换；单位和本人身份型不伪造案件成员。SOURCE-01仅列来源敏感动作的实施审查范围，具体用途/来源字段按对应任务确认，不将计划列表冒充代码覆盖。

`devLogin`保留契约明确的公开开发例外。内部推理、PoC liveness、框架文档路径单列边界，不改变73操作计数。未挂载操作必须先实现真实路由再测；路由不存在返回404不计作拒绝授权成功。
