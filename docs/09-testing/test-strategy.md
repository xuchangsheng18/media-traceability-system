# 分层测试策略

本包将资料校验、数据库约束行为、应用单元/契约/集成、安全、真实模型、性能与场景验收分开。当前只运行文档/实例校验和隔离SQL测试；应用、GPU、真实模型和公安生产环境测试未执行。

业务场景在test-scenarios.yaml，逐任务执行计划在task-test-scenarios.yaml。后者保留源测试要求与验收标准；运行时必须补入实际实现、确定数据、具体断言和环境，不使用空测试。任务卡中planned路径是待实现位置，不冒充已有测试文件。

测试记录含编号、关联需求/任务/版本、前置、数据摘要、操作主体、步骤、正常/异常预期、实际结果、时间、责任人和证据路径。结果分PASS/FAIL/NOT_EXECUTED；仅相关层通过，不自动关闭任务或审批。

Schema检查语法、类型、format、未知字段和分支；语义检查半开时间、坐标、failure_count、所有父组/人物/事件泄漏、失败响应不能含结论。SQL检查约束、作用域、撤销及不可变事实。运行服务后再做401/403、越权、幂等、陈旧ETag、取消旧lease、查毒故障、下载撤销/Range、证据包及批准失效等验证。

真实模型按固定MetricProtocol和封存访问制度独立执行，不用合成/Mock判断源准确率达标。负载固定混合比例、素材、模型、索引、资源、计时范围与错误分母；20/100口径待确认。恢复需隔离环境数据库、对象与授权/批准对账；同盘复制不作为灾备。

## 数据库基础修订的已实现检查

除了场景计划，本轮提供实际执行的`tests/sql/first-source-cases.json`与`scripts/validate_database_foundation.py`，覆盖30项首发排序与RLS检查；原25项SQL检查仍保留执行。`scripts/validate_database_contracts.py`覆盖字典、Schema及候选语义。以validation中的本轮报告及SQL摘要确定适用版本，不用这些结果替代完整应用集成或并发压力测试。

## 首发证据补充检查

当前first-source-cases.json包含48项排序、RLS及证据案例；原25项SQL检查保持执行。database-contract-report包含17项字典/来源/Schema与候选语义检查。任何“30项”旧记录属于0.2版本，不是当前全部案例数量。
