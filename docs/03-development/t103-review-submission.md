# T103复核提交与当前页内存草稿

本批接续既有上下文、历史及证据分页，实现T103-C05复核表单。开发负责人及指定复核人仍为徐昌胜；不登记本人已复核、工时或独立双人验收。源依赖和原验收完整保留。

复用现有GET /analysis/tasks/{id}/review-context和POST /reviews、ReviewContext/ReviewCreate/Review结构，不新增端点、字段、数据库迁移或策略。服务端已有追加review_record、review_evidence及审计的事务；当前实际入口没有接入正式RuleProvider及独立职责事实，仍会拒绝，不用测试提供者替代。

表单从服务端当前上下文固定任务、运行、结果、策略及预期复核版本；If-Match使用原样强ETag，不在客户端重算或猜造。缺ETag仍允许既有只读显示，但不得提交。仅当前身份具备review.read/review.perform且案件可见时准备提交；客户端不提交reviewer_id、case_id或approved标记。证据UUID格式/重复校验不等于事实或授权校验，最终由后端核对同快照、来源、对象及当前规则。

仅提供契约已有四种决定、1至4096码点理由、唯一证据UUID清单和防误操作确认。确认不等于独立批准；return_for_evidence/request_rerun只记录决定，不表示任务已退回或重算已启动。回执必须完整并与当前主体、请求任务/运行/结果/策略/预期复核版本、决定、理由和证据清单匹配，复核版本应为预期加一；失败不显示成功。

未确认请求固定body、Idempotency-Key、If-Match、上下文与身份。网络、超时、服务不可用或回执无法确认时不自动重试，不允许另造新请求，只能显式重试原请求；初次确定拒绝后重新读取上下文；原请求曾不确定时，后续4xx也不能证明首次未提交，继续保留原请求，不另造新写入。身份、单位、角色、权限、案件、任务、父上下文重读及卸载变化清除旧内容，迟到成功/错误不进入新上下文。

草稿仅保留在当前页面内存，不写localStorage/sessionStorage或服务器；离开、刷新、身份或上下文变化即清理。重新进入时应先查当前上下文及历史，不宣称可跨刷新恢复原请求或持久保存草稿。没有新增标注API或服务端草稿表。

完整开发浏览器初轮137通过、1处旧按钮数量断言失败；更正为总计8按钮及3个新增按钮逐个禁用，原读取断言保留。根流程同时修正过时只读文案及区域名，不改变提交逻辑，精确反向摘要验证见回执；保留一次原始七文件独立复核与更正证明，不冒称独立复核过全部新字节。实际测试数量、命令、源码摘要、审查及CI/同步状态见[回执](../00-project/validation/t103-review-submit-report.json)。浏览器使用自建传输夹具，只证明前端协议、拒绝和生命周期处理，不证明正式规则/真实身份/来源/后端E2E；本批后端及SQL未改，不重复未受影响的整套数据库回归。
