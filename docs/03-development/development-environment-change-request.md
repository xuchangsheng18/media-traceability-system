## 存储扩容方案和恢复条件

推荐在协调好的维护窗口使用Docker Desktop资源设置，将约98GiB磁盘上限增至512GiB。512GiB是本次建议操作目标，不是已批准的生产配额。另一方案是把本项目迁至独立Linux Engine及独立数据目录，隔离收益更大，但需要新引擎、许可/网络和迁移验证；只清理本项目缓存不能解决共享活动镜像约88GB的根本占用。当前安装的Desktop CLI未提供扩容子命令，不通过猜测配置键或在线截断磁盘文件执行。

维护流程为：记录全部运行容器及重启策略；确认维护授权；短停共享Desktop；对已解析的实际磁盘文件及配置作离线备份并校验；通过支持的资源设置扩大上限；启动引擎；只恢复维护前运行的容器；在PostgreSQL卷内重新读取df；核对本项目7服务、数据库迁移账本和对象/模型摘要；再在本项目获准范围内执行恢复与工程检查。失败时先保持服务停机状态，依据离线备份恢复原文件和配置，不以缩小新磁盘来恢复。

实施前必须明确对其他31个容器的停机影响。只复制运行中的Docker.raw不能作为一致的离线整机备份；减少磁盘上限也不是回滚方式。Docker磁盘位置与上限依据[官方资源设置](https://docs.docker.com/desktop/settings-and-maintenance/settings/)，磁盘位置操作及缩容后果见[官方Linux说明](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/linuxfaqs/)。
