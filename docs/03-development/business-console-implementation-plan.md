# 前后端开发优先：业务控制台实施计划

**Goal:** 在已有前端保留上传验证入口，新增连接真实业务接口的身份、审批及审计操作页面；不把PoC令牌、合成模型或页面存在当成业务验收。

**Architecture:** 复用Vue、现有业务OpenAPI生成类型及42操作后端，新增独立的内存业务会话和固定端点客户端。开发代理将`/business/api/v1`转给独立业务进程的`/api/v1`；原`/api`与`/poc`保留。候选规则只用于隔离测试，普通启动不安装合成权限，缺正式身份或策略时如实显示拒绝。

**Tech Stack:** 现有Vue3/TypeScript/Vite、Linux py310/FastAPI/PostgreSQL，不增加依赖、不改原锁、不创建Python候选。

**Spec:** [T001—T123执行顺序](t001-t123-development-sequence.md)、源T016/T018及现有`docs/03-api/openapi.yaml`。本轮用户明确要求先实施前后端，综合测试与验收后置；本页把该要求落到可审查代码，不新增公共字段、正式角色或共享迁移。

## Global Constraints

- 当前T014 P01—P07已有隔离实现及精确代码CI，直接复用，不重复生成方案或覆盖证据。
- 业务令牌只存在当前页面内存；切换身份清空页面结果、作废在途请求；不读取PoC令牌、存入浏览器持久存储或放入URL。
- 页面角色/权限只控制提示和按钮，服务端仍核验完整角色、单位、案件、对象、版本和审批。当前用户接口不可用时不建立已登录状态。
- 所有变更请求带幂等键；版本变更带服务端返回的ETag和expected_version。网络不确定时保留原请求用于相同幂等重试，不无条件换键。
- 审计查询当前契约仅有case_id/limit/cursor。时间、用户、对象筛选仅明确作用于当前页；完整服务端过滤仍待契约补充，不伪称已实现。
- 导出须填写真实批准ID、时间窗和用途，另外确认防误操作；该确认不替代业务审批。只经受控下载接口取字节，不使用object_ref绕过授权。
- 不补空接口填数，不自动授予sysadmin全部业务权限。未挂载资产/任务列表及真实模型适配仍按原任务逐批实施。
- 只读启动观察和本批构建/必要正反例同时执行；综合E2E、性能、安全专项、正式验收保持待办，已有CI命令不删除。

## Review Focus

1. 改令牌后旧请求才返回：客户端代际及取消机制拒绝旧响应，页面watch清空敏感结果。
2. 错误代理或重定向把Bearer发往另一站点：复用严格URL检查，拒绝重定向、不带浏览器cookie。
3. 用户以为按钮确认就是批准：写明二者作用，服务端拒绝不映射为成功；不生成operation_token。
4. 列表筛选改变后误用旧游标或旧版本提交：案件/筛选变化清空页，批准/撤销先读取ETag，冲突要求重新读取。
5. 原件URL可绕过审计：只提供固定授权下载端点，经fetch鉴权后创建短时本地下载URL并撤销。
