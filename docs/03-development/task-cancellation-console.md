## 页面行为及复用接口

| 操作 | 要求与结果 |
| --- | --- |
| 读取取消条件 | 必须有task.read及task.cancel；从已有任务编号读取getTaskExecution，核对任务、可见案件、正整数运行/控制版本及完整强ETag。 |
| 提交取消申请 | 只接受既有六种可请求前态；填写原因及适用批准编号、本人勾选确认；发送既有TaskAction，携带同一快照的If-Match及新幂等键。 |
| 接收受理回执 | 核对精确task_id、CANCEL_REQUESTED及本任务status_url；不跟随服务端任意链接，不把202或回执当作worker停止。 |
| 结果未知 | 网络异常、5xx或回执错配时冻结原请求及输入，仅重试原body、key和ETag；不因重试更换原因、批准或版本。 |
| 明确拒绝 | 权限、对象、版本或输入拒绝清除旧提交条件，需重新读取；刷新条件时清除旧勾选确认。 |
| 身份或任务变化 | 用户、单位、角色、权限、案件、身份代次或任务切换清除旧状态与表单，晚到响应不能恢复旧回执；服务端仍逐次授权。 |

新增`frontend/src/business/task-cancel.ts`控制器、`TaskCancelPanel.vue`组件并接入`TasksView.vue`。原有列表、状态和历史结果读取继续使用原控制器；取消条件与历史结果分开展示。

原因按既有4096字符上限校验，批准编号仅作已有契约输入；填写编号不授予权限。请求不存入浏览器持久化存储，不由页面读取或复制访问令牌。未知请求切换任务后不会自动重新提交；若返回该任务，应重新读取实际状态，由服务端版本和幂等约束处理冲突。
