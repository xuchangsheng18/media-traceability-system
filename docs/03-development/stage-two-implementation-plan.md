| 1 | 资源盘落实与生产组合选择，涉及T001—T010/T111—T120及对应卡 | 最近卷容量满足研发保护；重操作前复查，落实宿主/VM/容器配额与维护人；确定生产Python/OS/网络准入，单独环境锁定构建CI，不自动升级当前py310 |

| 3 | 唯一接口源补齐，13项IF-G01—13及关联任务 | 从现有OpenAPI/模型源和缺口登记逐项实施；上传/审批/复核/反馈/发布/导出异步终态查询、严格历史身份、ETag和外部协议。同步样例、SQL映射、追踪及4类生成类型后联调 |
| 4 | 调度与事件，T031—T039/T051—T060 | 已有36候选节点图和7事件需实际worker绑定；至少两实际Celery进程/独立队列演练重复、乱序、取消、超时续租、旧token、重试耗尽/死信和恢复。记录进程与消息ID、领取/取消/提交时间；不得用线程竞争证明多worker |

上表任务区间只便于导航，实际依赖以每张任务卡为准，不重排/删减170任务。批准规则必须匹配当前task/run/result/策略版本；RETURNED仍分补充同运行追加结果与重算新运行两路径。

生产恢复演练具体步骤：记录灾前有权写入序号/时间、SQL提交及对象VersionId/摘要；备份加WAL归档；在隔离且授权的另一主机恢复到指定点；从受控密钥恢复流程取密钥，不从Git拿凭据；重建全文/向量/传播索引；对账原件、历史结果、审计和索引版本；复验鉴权和批准绑定；记录开始故障、最后恢复有效写、服务恢复业务校验结束时间。RPO=故障时点与最后恢复有效写时点差；RTO=故障发生至业务核验恢复结束时间；保留未恢复条目和失败。当前目标值/异机/密钥流程未知，不记生产PASS。

制品和仓库治理见[运维离线交付](../10-deployment/stage-two-operations-and-offline-delivery.md)；实际输入可填写[stage-two-external-inputs.json](stage-two-external-inputs.json)。每项须记录证据而非只将状态改成完成。
