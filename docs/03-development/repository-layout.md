# 仓库目录与依赖边界

2026-10-13；第三阶段研发实施候选，正式批准/冻结未完成。

保留原13业务目录和原文件，增加data-pipeline/tools的代码边界。基础文件、.github、.codex和编辑器任务作为工具配置，不计作新增业务模块。原12模块/170任务范围不变。

| 目录 | 职责 | 构建/验证及边界 |
| --- | --- | --- |
| frontend | Vue界面与本地测试 | Node锁、TS检查/构建 |
| backend | PoC API/worker与版本迁移 | py310、pytest、隔离SQL |
| ai-services | 合成CPU推理/训练代码与模型声明 | py310；真实34能力另验 |
| shared-contracts | 从唯一源生成的类型 | 生成漂移检查，不另定义字段 |
| schemas | 模型/数据/工作流机器定义 | JSON Schema正反夹具 |
| datasets | 规划配置与小型自建元信息 | 实际素材与封存数据外置 |
| data-pipeline | 后续用途授权的数据处理代码预留 | 当前无完整业务管线 |
| tools | 工程辅助工具边界预留 | 不重复业务/契约实现 |
| deploy | 独立研发Compose/Docker构建配置 | 命名项目、卷不删 |
| config | 版本/锁/非敏感候选参数 | 真实凭据外置 |
| docs | 来源原件、需求/接口/数据库与状态 | 原件摘要与导航校验 |
| scripts | 统一开发、生成及验证程序 | dev.py与现有脚本保持关系 |
| tests | 自建单元/契约/集成计划与夹具 | 源任务计划不当执行结果 |
| tasks | 170原任务卡与执行映射 | 不改变源范围/工时 |
| prompts | 任务参考提示词 | 不作为实际授权/批准 |
依赖方向：前端经API取数据，后端管理授权/任务/结果，worker调用内部推理，能力请求/响应来自模型Schema；生成类型、SQL映射依靠对应唯一源。训练、推理、评估、模型卡与外部权重引用分别见ai-services及docs/06-algorithms，不复制第二模型目录。

禁止纳入Git：真实/敏感素材、大型数据集、权重、运行日志与制品包、凭据/连接秘密。普通Git只保存代码、配置模板、机器契约、文档和小型自建夹具。完整实际树通过`git ls-files`及docs完整索引查阅，预留目录不构成已实现管线。
