# T013：重启、历史凭据审查与恢复回切验证

2026-10-19。本批继续执行已批准的[身份设计](t013-keycloak-identity-design.md)和[8步计划](t013-keycloak-implementation-plan.md)第7、8步。实际开发负责人为徐昌胜。本批已形成IDP-17、18、20、21的限定研发证据，当前[执行报告](../00-project/validation/t013-recovery-report.json)、[故障日志RED/GREEN](../00-project/validation/t013-gateway-log-privacy-report.json)、[本批CI报告](../00-project/validation/t013-recovery-ci-report.json)和[22项台账](../00-project/validation/t013-keycloak-acceptance-ledger.json)分别记录实测和待决；T013整卡仍未关闭。

## 执行范围

1. 使用随机命名的`media-trace-identity-restore-xxxxxxxx`项目、独立网络和新数据卷，重建真实Keycloak/PostgreSQL/TLS网关。测试入口仅绑定本机回环和空闲端口。共享身份入口、现有数据库及原100包锁不作变更。
2. 取得真实授权码和令牌，记录realm、用户、客户端和公开签名密钥标识。重启三服务后复核持久状态；断开隔离数据库，要求就绪检查和认证均拒绝，恢复后正向请求成功。
3. 以签名、加密管道备份自建测试身份库，另用新卷恢复。备份发生在会话撤销和客户端secret轮换之前，先实测旧状态是否恢复，再清会话、提高not-before、撤下旧签名密钥并轮换API secret。旧access/refresh及旧secret必须失败，新身份仍按issuer+sub精确映射，不能获得未配置的业务权限。
4. 只在隔离项目内停止恢复副本并回到原测试卷，验证原状态和新凭据；不删除卷，不把切回旧软件等同于允许旧凭据恢复权限。
5. 检查可访问Git引用的全部可达原始blob、当前源码、当前保留的项目容器日志及本次托管CI日志。匹配已知私密运行值、完整JWT、私钥块和GitHub token材料；报告只保存范围、位置、数量及整份证据摘要，不输出匹配凭据。

## 边界和决定

复用现有证书、私密卷安装、备份签名/加密、独立卷恢复、逐次introspection及T012身份映射能力；没有引入新业务接口或修改业务数据库结构。新增恢复清理入口只接受随机临时验收realm，拒绝`master`和共享`media-trace`；中途失败保持该临时realm禁用。它不提供正式入口切换命令。

真实协议验证使用TLS和PKCE授权码交换。此次恢复测试由HTTP客户端提交自建用户登录表单，与既有真实浏览器协议测试分别记账，不互相冒充。测试密钥仅用于本批自建夹具，不代替正式备份密钥保管和异地灾备。

历史审查限定于实际列出的引用和保留证据。删除或过期日志、不可达历史、压缩二进制内部和无法识别的未知口令不因一次模式扫描被宣称已全面排除；任何有效发现需单独处置。生产恢复、共享身份服务重启、实名管理员/MFA/bootstrap交接、正式软件准入和T013实际复核仍按适用条件单独完成。

Python3.13/3.12候选继续暂缓，现有Python3.10.22继续沿用；本批验证不表示接受其维护或漏洞风险，也不关闭N01。

已发现并保留的失败：原镜像在隔离数据库停止后未报告DOWN。官方[健康检查说明](https://www.keycloak.org/observability/health)及[26.8.1升级说明](https://www.keycloak.org/docs/26.8.1/upgrading/)明确数据库检查还需启用metrics；原构建只启用health。当前修订为同一上游摘要构建时同时启用metrics，仅在隔离候选中验证，管理端口仍不对外发布。共享镜像标签、运行容器及既有`versions.json`中的已观测镜像ID不被本次候选替换；新候选的软件准入和后续采用需按实际制品另核。

网关的就绪子请求仅在内部网络访问既有管理端口9000，不转发Authorization、Cookie、请求正文或原查询串。认证数据转发继续使用原TLS链；公开健康/管理边界不放开。[Nginx auth_request官方说明](https://nginx.org/en/docs/http/ngx_http_auth_request_module.html)的非成功状态会拒绝本次访问。原始请求错误日志无法按普通访问日志定制，因此此身份HTTP入口使用固定类别/状态日志观察失败；全局启动/配置诊断、私有健康检查和指标保留。详细请求上下文不进入运行日志，正式集中审计与保留制度仍待实际环境确认。

新增冷启动、独立卷恢复和回切使真实live组运行量增加；只将整组执行器预算改为1800秒、托管身份job改为45分钟，适配完整流程。认证网络/SQL等待、45秒健康故障检查、原10秒撤销目标及300秒令牌断言均未放宽；业务执行器600秒预算未修改。独立复测通过不能抹去首轮超时。

首轮托管运行[39194234076](https://github.com/xuchangsheng18/media-traceability-system/actions/runs/39194234076)的243项身份测试、246项独立业务测试和32项基础检查通过，但后续安全门禁命中本批测试文件中的私钥头字面标记，整条流水线失败。已知运行凭据扫描通过，失败报告只列该自建测试文件。保留首轮失败、原门禁复现及报告摘要，将完整测试标记改为执行时拼接；完整私钥块检测断言和原安全门禁均保留。最终提交的流水线状态以本批CI报告中的实际重跑结果为准。
