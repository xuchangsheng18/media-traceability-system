2026-10-18，状态：PROPOSED_NOT_APPROVED。原生方案已批准使用当前py310做研发核验；本申请只处理新发现的上游3.10停止支持问题，不自动更改已确认版本锁。

[官方生命周期](https://devguide.python.org/versions/)列3.10于2026-10-01结束支持。已取得的Conda3.10.22包构建日期不能替代实际维护合同或安全补丁承诺。逐条漏洞和运行事实见[本轮复核](native-n01-license-vulnerability-runtime-review.md)。

## 拟验证范围

沿用既有TB-ADR-002的Python3.13主候选、3.12备选方向。批准后先查官方补丁版本及实际CPU依赖支持矩阵，再锁定精确解释器、来源和SHA256；不使用latest标签，不未经验证选Torch新版本，不假定原100个版本都有新解释器轮子。

1. 在项目私有候选目录生成新依赖求解方案，与原100包逐项比较；缺轮子、ABI冲突、许可或漏洞处置不足即报告，不静默替换。
2. 下载并验真解释器及依赖；记录完整构建/运行依赖、许可证、SBOM、漏洞来源及适用性。候选锁独立存放，原锁不动。
3. 在隔离环境运行项目类型、单元、接口/SQL契约及CPU推理测试，覆盖Base64规范编码与临时目录等受影响路径；需要公共契约改变时先另提设计，不直接修改。
4. 对比候选与当前py310的结果、行为差异、重建/恢复步骤及未通过项。完整记录失败，不降断言、不跳门禁。
5. 提交实际证据后由徐昌胜决定是否采用；采用和共享服务切换不属于本次验证授权。若继续3.10，须提供可核验的维护/补丁来源与有时限的风险决定，不能由助手编造。

## 修改边界及回退

仅新候选目录、新锁和对应报告；不安装系统包、不更改当前Conda环境、原100包锁、现有服务/数据或正式接口。候选验证失败可保留原环境继续既有研发，但N01正式原生准入仍受阻。未批准前不执行候选环境创建。

## 需要的决定

徐昌胜确认是否同意上述“独立验证受支持Python候选”的范围即可；无需提供密码、Token或私钥。这不是批准采用新版本，也不是批准现有安全风险。
