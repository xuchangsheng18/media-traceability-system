## 2. 已核实的现状与边界

| 现有能力 | 可以复用 | 不能据此推断 |
| --- | --- | --- |
| `Actor(user_id,org_id)`、`Scope(actor,case_id)` | 内部不可变主体和案件参数 | 单独构造 Scope 不代表经过认证或授权 |
| `Database.identity_transaction` | 事务局部 actor/org、拒绝超级用户和BYPASSRLS、T014根事务复查 | 当前没有单次请求的固定case_id数据库上下文 |
| `Database.transaction(scope)` | 检查该主体的案件成员关系 | 成员关系允许多个案件时，不等于所有SQL只能访问传入的一个案件 |
| 现有RLS与复合外键 | 单位/成员关系约束、跨单位目录约束和池复用测试 | 不能把64表快照对比当作64表所有CRUD已测试 |
| `RuleTarget`和授权证据 | 已验证主体、operation、org/case、对象/版本、来源、策略及恢复代际 | 缺失正式分类、人员、用途、委托和服务事实时不能生成ALLOW |
| `FileObjectStore.read(ObjectRef)` | 不可变版本、实际字节摘要和符号链接拒绝 | ObjectRef仅说明文件身份和完整性，不说明单位、案件或用途授权 |
| T014导出、历史读取与后台复查 | 现有审批、来源、期限、撤销、版本与事务检查 | 新DataScope不替代这些检查，也不增加已实现接口数 |

现有 `identity_transaction` 同时用于：对象定位、当前用户案件目录、单位策略/模型元数据、实际案件业务事务及后台事实读取。因此不能一律删除这些调用，也不能直接让所有无case_id事务全部放行。后续必须逐个迁移到明确的访问模式。

## 4. 内部DataScope与三种模式

保留现有Actor、Scope、ObjectRef字段和调用者可见的数据格式；新增内部不可变DataScope，不增加外部请求参数，不从HTTP头、队列消息或业务请求体直接反序列化授权范围。

| 字段 | 类型／含义 |
| --- | --- |
| actor | 已验证的Actor；不是客户端声明的用户或单位 |
| mode | CASE、ORGANIZATION或LOOKUP，未知模式拒绝 |
| case_id | CASE必填且非零UUID；其他模式为None |
| operation_id | 已登记的真实操作或工作操作；不接受任意自定义授权名称 |
| lookup_kind / lookup_id | 仅LOOKUP使用，绑定固定资源目录中的种类和精确对象，二者同时存在 |
| task_binding | 适用时由可信目标/ResultKey解析的task及run/result版本，不从未经核对的请求字段直接生成 |
| evidence_binding | 适用T014证据的稳定绑定摘要；不保存Bearer、密码或任意权限集合 |

三种模式的精确行为：

1. **CASE**：单位和案件必须同时等于已验证证据及当前Scope。任务／对象仍须在同一case内，由现有RuleTarget和关联关系核对。即使用户还属于其他案件，漏写WHERE的业务查询也不能返回这些其他案件的数据。
2. **ORGANIZATION**：仅用于现有单位级操作，例如单位策略/模型元数据和对应case_id为空的单位审计。不得据此直接读取案件业务表；当前用户的案件ID枚举经专门最小目录函数返回，不开放案件行。不使用零UUID伪装真实案件权限。既有单位游标内部占位格式若需兼容保留，仅用于游标绑定，不作为数据库授权范围。
3. **LOOKUP**：仅用于范围证据生成前，已验证主体对目标案件、单位对象种类或版本尚待确定的精确元数据定位。使用PostgreSQL只读事务；固定kind、ID、单位及适用有效成员关系约束；返回固定最小元数据，不提供通用SQL、任意表名或文件内容。不得枚举其他ID或其他资源表。定位结果还须进入CASE或ORGANIZATION授权，不直接放行业务。

生产构造入口分别消费现有Principal／AuthorizationEvidence和ExecutionSubject／WorkAuthorizationEvidence；后台不制造JWT。测试需要绕过真实身份时必须使用明确标记的合成适配器，应用默认装配不加载测试适配器。

不存在“管理员全部案件”、`allow_all`、调用者自报密级或未验证临时权限集合。业务管理员获得案件访问仍需要受控目录中的有效显式关系及相应功能/对象权限；姓名和角色名称本身不放行。

## 5. 请求、定位与事务的数据流

案件路径：凭据核验 → T014实际权限/对象证据 → 构造CASE DataScope → 同一根事务绑定actor/org/case/operation → 代际锁、角色与对象复查 → DAO/对象访问 → 提交或交付前复查。

仅对象ID路径：已验证Principal → 只读LOOKUP定位精确最小元数据 → T014核对该对象、单位/案件及适用来源 → 按真实目标构造CASE或ORGANIZATION DataScope → 实际业务查询。定位成功不直接返回业务内容。

单位路径：已验证Principal和当前单位操作证据 → ORGANIZATION DataScope → 仅相应单位元数据及单位审计。需要列出本人案件时走明确的成员ID目录入口，不能借单位模式查询全部案件内容。

LOOKUP只在范围证据生成前执行，不持有T014栅栏的共享行锁；其输出由后续CASE/ORGANIZATION根事务再次核验，防止定位与使用之间变化。已有范围证据的路由辅助定位直接复用原CASE/ORGANIZATION，不降级到LOOKUP。这样不把需要FOR SHARE的授权栅栏放入PostgreSQL只读事务。本人案件ID目录使用下述固定函数，在现有ORGANIZATION栅栏事务中调用，不伪装为另一个只读根事务。

`Database.transaction(scope)`必须核对传入Scope与当前证据范围；同actor但不同case也拒绝。嵌套事务不能更换actor/org/case或把CASE升级为更宽模式。task_binding仅可在同一可信目标下由服务器进一步解析并缩小，不得换到另一个任务或扩大已固定版本。事务结束、异常和连接池复用必须清空所有局部范围值；不能沿用上一请求的mode或case。T014原代际锁排序、真实期限、撤销复查及5秒刷新约束保留；DataScope绑定不把事实续期时间误当稳定人员/授权身份，也不把5秒刷新改成长作业超时。

内部不带HTTP证据的受控生产者仍需现有来源/案件授权及适用工作证据；不能因为它是后台或内部方法就默认授权。只传Actor或Scope不构成认证依据。

实际业务访问入口缺少上述证据时拒绝，不保留“直接构造Scope即可放行”的兼容后门。低层RLS/迁移测试可在自建数据库中显式设置受控测试上下文，原隔离SQL断言保留；它们证明数据过滤，不宣称完成身份认证。不得为了维持测试通过而给生产入口加入默认ALLOW或测试模式开关。

## 6. 增量数据库设计

拟新增`0010_data_scope.sql`，实施前复查0009仍为本分支最新迁移；若其他工作流已占用版本，重新确定新版本，不覆盖已有文件。

新增读取事务局部范围的固定函数及AS RESTRICTIVE策略；对已有permissive策略作AND收紧，不新增一条宽泛ALLOW与原策略相OR。缺失、空值、无效UUID、未知mode或不完整绑定拒绝。SQL设置来自服务器受控构造器，禁止把客户端提供的设置串拼进SQL。

按实际64表逐表分类，不能只按列名自动推定安全含义：

- 案件业务表：CASE仅允许同org、同case且原成员关系有效；LOOKUP仅对固定资源目录允许精确主键元数据定位，其他表在LOOKUP拒绝；ORGANIZATION拒绝。
- 单位业务表：保留当前org约束和操作权限；CASE调用如需读取本单位模型/策略事实，仍须原接口/条件，不因该行是单位级而扩大功能权限。LOOKUP仅允许固定目录中精确单位对象的最小元数据定位。
- 身份/角色/成员目录：保留当前本人可见及最小受限函数边界；当前用户案件枚举使用专门最小目录函数，不开放一般案件或其他人员数据。
- `audit_event`等同时含单位和案件行的表：CASE仅同case行，ORGANIZATION仅本单位的case_id为空行，保留原审计不可变约束。
- `authorization_epoch`及不授予runtime直接访问的目录/内部表：继续禁止直接访问；不能为“统一64表”新增runtime表权限。

LOOKUP所需的资源种类、主键和允许投影形成单一固定目录，来源为当前真实定位调用。SQL策略只允许该目录的精确行；应用定位端口只返回case/org、版本和后续授权必需字段，不返回任意行JSON或对象字节。成员枚举限本人且保留有效成员关系约束。

拟增加固定无任意SQL参数的`mt.current_actor_case_ids()`目录函数，只从服务器绑定的actor/org读取有效本人成员案件ID；返回case_id一列。调用保留T014当前用户权限及后续逐case.read核验。函数owner读取目录的权限、固定search_path和EXECUTE ACL明确测试，runtime不获得目录管理继承或直接案件表宽读权限。这不是一般跨案件读取函数。

数据库新增统一限制的本批硬边界是单位/案件和精确LOOKUP行。任务与历史版本同时经DataScope.task_binding、现有任务/结果关联及DAO谓词限制；不声称所有含task_id的表已由一条通用RLS自动完成任务隔离。对应任务/版本错配与批量查询必须有实际反例。

不向业务runtime授予SUPERUSER、BYPASSRLS、目录管理组或新的任意SECURITY DEFINER执行能力。固定函数约束search_path与EXECUTE ACL；迁移owner不是超级用户的升级、查询和恢复场景也必须实测。事务配置是应用内的数据范围约束，不替代数据库账号认证，也不声称抵抗已完全控制runtime数据库凭据的攻击者。

不新增业务表/字段，不改825字段历史字典，不改0001—0009。新建库、0009升级、重复执行、部分失败回滚和实际隔离dump/restore分别测试。共享安装、停写切换和现场采用均不在本设计批准范围。

## 7. DAO与关联对象核对

逐调用记录输入DataScope、目标表、org/case/task/object过滤、关联来源、返回投影、分页/计数/游标，以及写入后的结果绑定。

当前范围包括上传会话/分片/导入、历史task/run/result读取、审批/复核、任务节点/执行、审计/导出/反馈，以及单位策略/模型元数据和当前用户目录。其余31个未挂载操作保留未实现状态；本批为后续DAO提供约束，不冒充已完成这些业务。

关联查询必须同时关联org、case和适用task/run/result/version；只匹配一个UUID不自动证明同一案件。批量接口先限制范围再分页、计数及生成游标；跨案件或越权条目不能进入页数、摘要或缓存。沿用T014已实现的逐项分类/用途/来源检查，未知权威事实仍503，不按允许处理。

CASE级允许也不能自动代表集合内所有对象的密级/用途允许。沿用T014复核列表的做法，形成统一内部范围筛选端口：在同一连接接收DataScope、原集合operation和固定ResourceBinding候选，按当前操作适用的逐对象分类、用途、来源及所有权条件返回精确允许ID。它复用原功能权限，不借用另一个操作的权限名称，也不接受客户端自报允许ID。

SQL先限制org/case/task及候选状态，再按可信逐对象结果得到允许ID，最后在SQL中限制分页/计数/游标；不能先LIMIT再删除越权条目。403/404明确不可见条目可排除，未知提供者/查询故障503使本次读取失败；空允许集合返回合法空页。返回前复查已选对象和允许集合绑定；原游标格式及秘密不变，当前范围变化使旧游标失效，不替它续权。完整候选核查的容量仍需后续负载验证，不声称此设计已经满足大规模性能目标。

## 8. 对象字节、上传与导出

保留低层ObjectStore协议及不可变摘要检查，在业务层增加统一的受范围约束访问入口。输入必须同时包含DataScope、精确ObjectRef及业务绑定类型，不能公开一个接受任意ObjectRef的业务下载入口。

实际绑定分开处理：

- 上传分片：通过upload_part与upload_session的org/case/upload/part、版本及摘要定位，核对上传主体和来源用途；不能假定尚未完成的分片已存在object_version中。
- 媒体/历史输入：object_version与media_asset或历史结果精确关联，保留每个实际来源的授权；不以任意同case对象替代任务输入。
- 导出制品：精确绑定audit_export、artifact_ref、已登记object_version、大小、有效期及适用审批/职责证据；复用现有Export.check和交付前复查，不只校验文件哈希。
- 模型/其他结果制品：沿用实际任务、模型/发布和结果版本绑定；缺对应真实提供者或绑定时拒绝，不把测试制品当真实模型结果。

逐个迁移当前imports、reviews、exports、history、inference及upload worker中的字节读取入口；记录尚未挂载/无实际生产者的路径，不省略或宣称它们已正式可用。使用Spy验证越权在底层read调用前被拒绝。

写对象前核对适用范围；文件和数据库不是一个原子事务。发生并发撤销、数据库回滚或接收失败时，不发布业务引用，沿用精确孤儿记录，不伪称未产生任何临时字节，也不自动删除证据或其他工作流数据。真实S3/SeaweedFS现场部署与对象端凭据隔离另验。

## 9. 错误和拒绝行为

保留T014既有语义：未认证401，明确无功能权限403，范围外/不可见资源404，绑定/版本冲突按当前契约，缺权威提供者或内部范围证据不一致503。响应不包含跨案件存在性、SQL、堆栈、令牌、真实配置或文件路径。

新增DataScope不会吞掉数据库/权限查询故障，也不会把未知事实过滤成允许。LOOKUP写操作拒绝、ORGANIZATION读取案件内容拒绝；撤销和失效后现有上下文不自动续权。游标保留原合法格式、密钥和D02严格编码校验，不因新设计擅自换签名或接受范围。
