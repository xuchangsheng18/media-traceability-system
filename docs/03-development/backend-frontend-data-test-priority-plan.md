# T001—T123后端、前端、数据与测试优先实施

2026-10-21：依据用户本轮要求，按原任务编号及实际依赖，优先完善backend、frontend、data和test。T124及以后保持范围外；170任务总目录可以随已验证子步骤重新生成，但不因此实施范围外功能。沿用当前Linux/py310/CPU研发边界、原100包锁和已有CI，Python候选继续暂缓。

## 选择原则

- 在相应类别内优先较早任务和已有接口的完整用户流程；不能为数字顺序绕过前置，也不因整卡未关闭而重复已验证子范围。
- 后端先实现或修复真实事务、权限、幂等和错误路径，前端再接相同接口；数据工具仅处理已有明确契约的范围。开发必要测试同时执行，综合安全、性能和正式验收另列。
- 尚缺真实身份、来源权威、正式分类、模型制品、授权数据或资源时，先完成可独立核验代码，保持相应动作拒绝；不生成成功占位结果。

## 本批实施清单

- [x] **后端／T021**：核对现有`syncSourceAuthorization`成功链与严格SOURCE_WRITE保护，先补真实SQL/HTTP失败回归。按现有`SourceSyncRequest`、`SourceAuthorizationUpdate`和Source契约，保护事务前后的权威绑定、版本、ETag、幂等及审计；提供者变化或异常必须回滚，重放不能返回已失效的授权成功。不新增接口字段、正式来源适配器或共享迁移。
- [x] **前端／T021**：在来源详情保留服务端实际ETag后增加授权同步操作。只发送`expected_version`，使用原幂等键及If-Match；未确认旧意图不能因新GET或409/412而悄悄换键。身份、案件、权限或详情变化清理旧展示和不可复用意图；真实提供者缺失仍如实显示拒绝，不办理人工授权批准。
- [x] **数据／T109**：提供独立离线标注质检CLI，显式读取输入文件，使用固定本地D01—D15及common Schema，不联网、不改输入、不写业务库。检查Schema、时间/区域边界，D03/D04按自身`duration_ms`检查；缺可信时长、掩码字节/尺寸、双人独立和仲裁均报告未验证。保留unknown/insufficient。若提供批内冲突和确定性抽样，仅作机械质检，不认定业务仲裁或标签质量达标；不跨入T126的数据卡/冻结/训练准入。
- [x] **测试／T021、T109及适用门禁**：每个行为先观察失败再实现。数据库测试仅在新建隔离库串行运行；前端执行类型、格式、lint、单元、构建和浏览器流程，数据工具执行正反例及CLI拒绝测试。权限变动执行原完整门禁和失败探针，不调宽超时、跳过断言或扫描。
- [ ] **导航与交付**：逐项更新真实C/R子步骤、剩余工作、123任务顺序和170任务总导航；实际负责人、工时及人工作业不编造。推送既有功能分支并同步Linux源码，精确绑定CI；不合并main、不重启共享服务、不接受漏洞或Python维护风险。

## 文件与执行边界

后端限于现有来源同步服务/路由、权限事务所需最小改动和相应测试；前端限于来源控制器、页面及浏览器回归。数据限于独立标注校验脚本/模块、测试和使用说明，不修改既有Schema。资料更新限于关联台账、索引、计划和实际回执。所有范围均复用已有公共类型、错误处理和版本约束。
