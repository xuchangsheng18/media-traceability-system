# 仓库和分支治理评审材料

2026-10-13；第三阶段研发实施候选，正式批准/冻结未完成。

评审输入为第三阶段16步、[平台选择](repository-platform-options.md)、[结构决策](repository-structure-decision.md)、[目录](repository-layout.md)、[账号矩阵](repository-access-control.md)、[权限边界](codex-permission-boundary.md)及当前技术执行基线。正式负责人、评审会议与日期待确定。

| 评审项 | 研发候选 | 正式决定/验证 |
| --- | --- | --- |
| 仓库/模式 | 沿用指定私有GitHub Monorepo | 生产代码平台/准入待确认 |
| 主/开发分支 | 已有main；develop是否需要待定 | 不为模板另建develop；实际策略待批准 |
| 变更分支 | feature/Txxx-描述、fix/Txxx-描述、release/版本候选 | 真实责任人/发布边界待定 |
| Code Review | 建议至少一名独立有权评审；敏感更改拟双人 | 实际人数、豁免和管理员绕过规则待定 |
| CODEOWNERS | 实际仓库所有者兜底；专业账号未提供 | 不能证明强制评审已生效 |
| CI | 原25CPU工程门禁加第三阶段输入/命令/质量验证 | 生效required checks和失败不可合并实测待落实 |
| 标签/发布 | 不自动打正式基线标签、不发布镜像/生产 | 发布责任人、签名/保护标签及离线制品待落实 |
| 紧急修复与分支清理 | 限定范围、保留复核与恢复证据；不删卷/源件 | 正式紧急授权和保留周期待批准 |

评审议程：逐项确认输入/责任人，复核每项实际证据和未执行项，决定接受范围及剩余条件；记录批准人实际身份、日期、决定引用、适用环境/期限及拒绝原因。当前[输入表](stage-three/external-inputs.json)所有正式决定字段为空；不得把当前同步提交或工程PASS当会议批准。

主要风险：生产技术基线未冻结、实际人员未确定、主分支保护未证实/套餐限制、研发Docker虚拟机数据盘容量不足、GPU/真实模型/授权数据未落实、扫描跳过CPU Torch发行包、Windows原生环境未验证。这些不妨碍明确范围内的合成CPU基础研发，但影响正式冻结/对应生产能力。
