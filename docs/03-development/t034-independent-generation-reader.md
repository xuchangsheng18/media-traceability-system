# T034独立恢复代际读取器与f10回归复核

本批依据已批准的[I01—I05计划](t034-creation-implementation-plan.md)及[E03/E04研发设计](t034-internal-development-decisions.md)，补充真实文件读取适配器。开发及指定复核人为徐昌胜；自动代码审查不代表其本人已经复核。精确源码、测试及CI观察见[本批回执](../00-project/validation/t034-independent-generation-reader-report.json)。

## 实现和接入边界

`permissions/generation_manifest.py`实现既有`GenerationReader.read() -> GenerationProof`协议，可作为`AuthorizationFence`的显式`generations`参数。它从数据库备份之外、由调用方明确指定的Linux私有文件读取；不查询数据库来为恢复代际自证，不自动创建、续期或签署文件，不注册默认提供方。既有应用工厂仍通过显式`authorization_fence`依赖接收栅栏；本批没有向共享应用注入实例。

调用方必须独立固定`GenerationIdentity`中的数据库名/OID、策略版本/SHA、恢复代际及最低epoch；这些配置不能从待验证文件本身推导。严格JSON仅包含`schema_version=1.0.0`、这六个绑定字段及`confirmed_at`/`valid_until`两个Unix秒时间字段。文件minimum_epoch允许高于配置下限，事务栅栏仍须核对其不高于当前持锁epoch。字段/类型、重复键、NaN/Infinity、空/超16KiB、未来/过期及超过显式期限均拒绝；研发期限上限沿已批准E04的30秒，不能靠读取动作延长证据。

Linux读取逐级禁止符号链接；祖先目录须由root或当前账号持有且不向其他用户/组开放写权限，root持有的sticky临时目录例外。直接保管目录须归当前账号且不向组/其他用户开放，文件须为同账号的单链接普通文件、0400或0600。描述符有界读取后复核文件和整个目录链的身份/连接关系；文件替换、祖先目录移走或权限变化拒绝。仓库内文件不能作为私密权威来源。每次实际重读，删除/撤销立即失效，时钟和已接受的确认时间/epoch不能回退；即使一次读取因过期失败，已观察时间也不能回退使旧证据复活。

这是一条文件保管信任路径，不声称已验证GPG签名、独立管理员、硬件密钥或组织审批。仅从协议层接入现有事务栅栏并完成自建夹具测试。实际代际维护渠道尚未建立，不能为了演示生成循环续期脚本或把备份内文件复制回来自动确认恢复。

## 失败复现和验证

- 新组件入口先实际失败，再实现；独立审查指出祖先目录替换及失败观察后的时钟回退，三个负例均先实际失败，再修复并复验。
- f10源码的旧OpenAPI断言实际失败为`52 == 51`。本批精确更新为52个外部操作、1个内部操作，并新增`createTask`、`TaskCreate`及202 `Accepted`引用核对；未删除或降低旧权限/错误断言。
- f10的CI运行39945824436中，foundation完整业务已正常结束，共2327项、唯一失败是同一OpenAPI断言，`complete=true`，没有超时。不能把这个旧提交结果写成修复后源码全套通过。
- 上一轮Linux直接完整回归在1800秒后没有最终回执，仍是未完成；本批目标定位的权限撤销文件17项通过，不能据此认定整个Linux超时根因已经解决。Linux最终完整回归仍待单独取得终态，不增加预算或并行数据库套件。

最终测试数量和实际命令以回执为准；原100包锁、py310、CI、安全扫描和两个失败探针保持，算法及Python候选继续暂缓。T034仍4条已证子步骤/4组剩余，不新增整卡验收或完成百分比。
