## 新增报告字段

[verify_business_foundation.py](../../scripts/verify_business_foundation.py)在原报告和标准输出中加入`failure_diagnostics`：

| 字段 | 含义及限制 |
| --- | --- |
| `items[].nodeid` | 仓库中实际存在的`tests/business/test_*.py::测试函数`，或该文件中实际定义的`Test类::测试方法`；用源码AST核对，不执行源码来生成标识 |
| `items[].kind` | 仅JUnit结构标签`failure`或`error`，不是原始异常类型或消息 |
| `items[].testcase_index` | 当前JUnit中从0开始的testcase序号；只用于同份报告定位，不是稳定业务编号 |
| `omitted` | 未能绑定已知源码或超过20条输出上限的失败/错误项数量；省略诊断不使失败变成通过 |
| `parameters_and_failure_text_published` | 固定为false；参数值、message、type及正文不进入报告或标准输出 |

参数化用例只输出函数级选择器。排查时在新建隔离测试环境运行该函数的全部参数；不要将口令、DSN、令牌或原始traceback复制到公开仓库。未知或不在当前源码中定义的模块、类、函数继续省略。仅导入/继承而未在该文件定义的测试可能省略，原总数和失败门禁仍有效。

## 保持的门禁

原pytest命令、1800秒上限、隔离目标检查、原100包锁、CI工作流及failure-probe均未改变。pytest非零、任一失败/错误/跳过、没有实际测试，仍不能通过。原始日志不因此公开，临时JUnit保管方式也未改变；这是增加安全索引，不是恢复已删除的旧traceback。

本批用自建无敏感夹具验证已知选择器、未知选择器拒绝、参数及失败文本脱敏、20条上限和缺失JUnit，并真实运行失败、跳过、通过三类子进程来核对退出语义。相邻资料与路由登记检查配套执行；数量以回执为准，不将这些夹具当业务功能通过。
