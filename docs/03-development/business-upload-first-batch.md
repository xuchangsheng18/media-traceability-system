## 当前已实现

业务入口为`/#/business/uploads`，导航名称“业务上传”。原PoC入口保留，用途与业务上传分别展示。

| 功能 | 实际实现与约束 |
| --- | --- |
| 案件与来源 | 只选CurrentUser.case_ids中的已有案件；读取案件内来源，只有verified、upload用途、有效期内的来源可选择。案件/用户/来源版本/权限变化清除旧文件、会话和晚回复；来源自然到期也主动清除。 |
| 初始化 | 精确发送UploadCreate六字段；浏览器计算文件SHA-256，保存本页原始文件绑定。网络结果未知只允许原内容、原幂等键重试，不重复创建。 |
| 二进制分片 | 复用业务会话私有令牌、取消、超时和401处理，使用新增putPart内部方法；按服务端part_size_bytes切Blob，发送实际摘要及幂等键，浏览器生成Content-Length。 |
| 本页续传 | 保留原文件，读取状态和完整分片分页，逐片复算本地摘要、大小/编号、游标与会话版本，再读状态核对版本和汇总；分页中变化则放弃累计结果，从头重试。未知分片只重试原字节与原键。 |
| 完成与进度 | 只提交已核对的连续完整parts。202原回执单独展示，不能替代当前状态；只有GET返回COMPLETED＋VALID＋asset_id时展示资产交接。可停止自动查询并手动刷新。 |
| 资产交接 | 使用当前案件及实际asset_id进入既有资产页；详情、下载仍按既有权限与固定对象验证，不绕过后端。 |

状态及分片GET的实际权限是`asset.upload`，与OpenAPI的x-required-permission、当前路由和后端相同；部分旧描述写asset.read只作历史文字问题，不据此放开权限。来源列表另需source.read。

## 使用边界

- 当前只支持PNG/JPEG；前端接受文件不证明媒体解码、安全扫描或后台worker已通过。
- 页面默认8MiB摘要内存预算，可在绑定会话前显式调整；最多10,000片是本页内存/操作资源保护，均不是正式业务配额或生产并发指标。服务端原限制继续生效。
- 本页不持久化令牌、文件或恢复私钥。离开/刷新后不支持仅凭upload_id恢复；状态接口没有原文件名、来源和完整摘要，不能由编号猜原绑定。
- “开始另一文件”只清理本页已确认上下文，不删除服务端旧会话和分片；未知变更结果时该按钮锁定，清理策略仍待T023验收。
- 完成接口同键重放可能始终返回最初VALIDATING回执，实际状态以后续GET为准。自动刷新最多30次、间隔2秒；耗尽后仍可手动查询，不凭超时把服务端改为成功或失败。
- 此次复用已有五个后端接口、数据库及worker源码，不新增表、迁移、公共字段、业务状态、依赖或共享服务配置。源码同步不表示已有Linux预览已加载新页面。
