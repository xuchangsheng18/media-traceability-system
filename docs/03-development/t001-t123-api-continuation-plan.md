# T001—T123前后端续建：权限回归与剩余接口

本轮依据用户继续开发、保留CI并同步三端的授权实施。优先修复权限回归超时，再按已有契约和真实依赖实现可验证的接口，补齐前端资产与任务读取。原100包锁、共享环境、Python候选暂缓和正式默认拒绝边界不变。

## 实施顺序与边界

1. 复查27项未挂载操作，逐项列原任务、契约、已有SQL/权限能力、缺失生产者及下一步。范围不能以挂载空路由或返回假数据关闭；T124以后的源任务仍单列。
2. 修复权限目录重复YAML解析：每次读取真实契约字节并计算摘要，仅复用校验成功的不可变结构；文件内容变化、缺失和非法内容继续重新校验或拒绝。缓存不保存身份、权限决定、数据库事实或授权有效期。用内容变化、并发、调用方修改隔离及原权限测试证明语义不变，再执行原1200秒完整回归。
3. 修正最新托管CI发现的异构JSON测试夹具类型声明，保留原断言和静态检查；失败记录不改写成通过。
4. 按已有Report契约新增getReport：读取已持久化报告、证据和固定对象版本；逐项核验单位、案件、任务与运行/结果版本。无证据、错绑或来源撤销时拒绝；不生成报告、不开放文件下载。新增0013迁移只扩固定查找清单和报告授权元数据，不改0001—0012及当前演示库。
5. 前端增加案件内资产分页/详情、当前任务分页并衔接现有任务历史页。仅调用真实GET；明确鉴权、空数据、错误和功能待实现状态。修改案件/选择或断开身份后丢弃旧响应，不推算模型结果或完成百分比。
6. 将新接口加入统一鉴权、无权限、正式规则缺失、权限来源故障和事务尾部复核的必需回归。执行类型、格式、单元、隔离数据库迁移、完整权限及失败探针、前端和适用CI检查。失败探针必须证明断言失败会阻断。
7. 按实际证据更新任务子步骤、123项实现清单、170任务导航及文档索引；未满足整任务验收条件不标整任务完成。普通推送既有分支并同步Linux源码，分别记录源码、托管CI和实际运行服务版本。

## 文件分工

- 权限性能：`backend/business_app/permissions/catalog.py`及独立缓存回归；不调整CI超时或跳过旧测试。
- 报告读取：`registry_reads.py`、`registry_router.py`、0013增量迁移及相应测试；公共入口、对象事实和门禁由主会话统一接线。
- 前端：资产页、案件任务列表组件、只读请求控制器、导航及现有浏览器回归。
- 交付资料：剩余接口逐项台账、验证回执、任务状态与现有总导航。私有运行配置及临时日志不入库。

## 验收口径

每个新接口必须有实际持久层读取及授权回归；每个前端入口必须有正常、拒绝和请求竞态覆盖。完整权限回归须在既有1200秒上限内真实完成。新源码CI与旧源码结果分别绑定精确提交；尚在运行、失败和未执行均如实登记。源码同步不等于迁移或重启共享服务，更不等于生产准入、真实模型验收或170任务全部完成。
