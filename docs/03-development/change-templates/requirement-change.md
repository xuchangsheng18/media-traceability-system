# 需求变更记录模板

使用时复制到本次变更记录，填写真实输入并关联PR。模板状态为DRAFT，空字段表示待落实，不表示同意变更。

| 字段 | 本次填写 |
| --- | --- |
| 变更编号 状态 日期 | 填写真实编号；DRAFT / REVIEWED / APPROVED / REJECTED |
| 提出人 实际责任人 审核决定引用 | 填写实际信息；未知保留null |
| 来源文件 版本 章节及摘要 | 填写权威来源与原文定位 |
| 需求 用例 任务及原验收标准 | 填写FR/ER/UC/T编号，不改写原170任务来隐藏工作 |

## 问题和拟议行为

写明触发条件、当前行为、拟议行为和边界。分别标明来源原要求、本次提案、已获授权的选择；给出一组可核对的前后示例。

## 影响核对

- 范围：列受影响的模块、需求、任务和依赖；保留12模块及不少于3类场景，功能删减必须明确披露。
- 契约：列唯一OpenAPI、事件、模型/数据集Schema、SQL迁移、字段映射、生成类型及客户端的具体文件。
- 权限与数据：列身份/案件/单位范围、来源用途、审批/复核/保存规则和真实依据；缺失时写明拒绝动作。
- 计划：列实际工作量、人员、交付依赖及影响；占位人员和假设日期不能填作事实。

## 验证与验收

列正常、异常、越权、版本冲突和回归用例。记录真实命令、输入与代码版本、环境、结果及报告引用；分别列PASS、FAIL、NOT_EXECUTED及有依据的NOT_APPLICABLE。模板或绿色CI不能替代业务验收。

## 迁移 回退与决定

说明兼容期、存量历史、前向修复/回退触发条件及恢复核对；不覆盖原件和旧结果。填写实际有权决定、日期、适用范围、例外和证据；未提供决定保持DRAFT或REVIEWED，正式冻结另行处理。
