# 模型变更记录模板

复制后填写本次事实。模型能力契约、合成演示、真实业务模型及生产发布分别判定，未填信息不能自动补为通过。

| 字段 | 本次填写 |
| --- | --- |
| 变更编号 状态 实际负责人 | 实际编号；DRAFT；未知责任人留null |
| 能力与模型版本 | M编号、名称、版本、原生框架及后端 |
| 权重与物料 | 来源、SHA256、许可和本次用途依据 |
| 代码 数据 环境 | Git提交、数据版本/摘要、精确软件硬件和CPU/GPU |

## 输入输出与兼容

列输入字节/像素的实际来源、原件/分析副本、前后处理、标签/阈值、mapping_version、Schema及索引版本。说明向量维数/度量、缺模态、部分能力、失败/超时行为及旧客户端兼容。字段变化同步唯一契约、生成类型、映射和业务访问。

## 数据和评测

记录来源/用途授权、分组划分、去重/脱敏/质检、校准集和独立封存测试集，禁止将封存集用于训练、调参或难例回流。给出真实样本数量、分层、指标协议、阈值来源、误差与未知项；没有真实数据/GPU的项目保持NOT_EXECUTED。

## 发布包与验证

逐能力准备ModelReleaseBundle：权重、配置、Schema、模型卡、评测、代码/数据/制品摘要及许可。原生与转换/量化后端分别验证数值、精度、资源和真实样例，不强迫全部能力使用ONNX。列故障、并发、权限和版本兼容测试及真实报告。

## 灰度 回退与决定

写明灰度范围、监测/停止条件、旧模型和兼容索引恢复、在途任务及历史结果处理。回退不能混合不同模型/前处理向量；旧结果保持原版本。记录实际审批及发布执行证据，模型操作查询接口存在不表示模型已发布。
