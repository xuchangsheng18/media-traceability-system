## 实际修改

- [采集器](../../scripts/identity/checks.py)仅对指定测试、当前锁定pytest的普通failure/call形状收集新理由。第一行必须精确；带type、setup/teardown/error或其他测试不获得新理由，仅在URL、参数或failure正文出现的理由码不采纳。参数化名称和规范首行后的解释均不发布。原有静态通用诊断保留。
- [真实故障测试](../../tests/identity/test_recovery_live.py)的7条原断言仅增加固定理由码；不拆复合条件。等待45秒、重启就绪180秒、`pytest.raises(BusinessError)`和finally恢复均不改。
- [诊断回归](../../tests/platform/test_t013_identity_checks.py)验证来源静态约束、错误形状、私有文本隔离、实际子pytest格式和断言语义；失败仍为FAIL，不把固定码解释为可认证根因。

缺少预期异常仅识别实测第一行`Failed: DID NOT RAISE BusinessError`；未知格式保留失败而不猜原因。JUnit若被完整伪造，采集器无法单独鉴真，仍须同时核对所属CI作业、准确提交和源码摘要。
