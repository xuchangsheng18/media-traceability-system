# T024目标上传队列隔离与旧队列边界

本批为T024-C05限定工程修复。开发负责人及指定复核人沿用徐昌胜；责任登记不等于已执行本人复核、独立双人验收或投入/日期确认。现有CI门禁、原100包锁和全部170项源任务及依赖保持。

原实现使用同案件共享队列，目标上传专属消费者可能先取到另一上传事件，并按既有绑定规则拒绝；因此后目标先消费不能正常进展。本批初轮测试因夹具完成上传返回409而未进入目标故障，该失败保留且不当产品RED；随后在真实RabbitMQ、随机隔离PostgreSQL及独立进程自建夹具中复现实际目标绑定故障，再改为v2单位/案件/上传三元组绑定的目标独立队列。每次发布和消费仍保留真实目标授权、事件绑定、事务及提交后ACK；错投事件继续拒绝、不ACK，不将吞掉其他上传事件当作修复。

本批实际证明范围是同一案件内两个不同上传，在后目标先消费时仍能各自进展，以及受影响上传/工作授权回归。最终103项受影响测试、失败探针、Ruff/格式/类型与精确四文件摘要、真实RED复核和一次新鲜源码审查见[专项回执](../00-project/validation/t024-upload-queue-isolation-report.json)。测试采用真实队列/隔离数据库和测试身份权威，不等于真实机构身份/正式工作委托或实际对象存储组合验收；无后端全库回归或前端修改则不继承其余检查为本批fresh。

旧case队列保留，不自动搬运、清空或删除消息；本轮没有切换共享worker/outbox或共享服务。现存旧队列库存、消息已发布状态、重投幂等和回退必须另行盘点并形成获准采用/恢复方案。v2队列按上传持久化，本轮没有TTL、自动清理或容量采用验证；完成后空队列可能累积，实际采用前须验证安全清理与容量，不能删除尚有未确认交付的队列。源码同步不代表部署采用。此修复不宣称解决同一上传多消费者公平、毒消息等待/死信处置、长期运行入口、临时分片和孤立对象清理或完整恢复组合。

本批只增加T024-C05一条已证子步骤：T024为5条已证/3组剩余，T001—T123累计151条已证、434组剩余，全部170任务622组剩余、整卡验收0项。最新CI及本地/GitHub/Linux精确提交以后续回执实际观察为准，不把隔离回归视为全部CI通过。Python候选、算法、模型、训练和效果评测继续暂缓。
