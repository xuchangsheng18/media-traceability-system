# T001—T123资源与登记接口续建计划

状态：已获当前会话批量开发授权；本批沿用已确认契约和权限设计。Python候选继续暂缓，共享环境及原100包锁不变。

本批解决可独立实施的四个现有接口：`downloadAsset`、`createSource`、`listModels`、`listEvaluations`。它们分别对应T025/T030、T021和模型登记/评测记录读取任务中的子范围；挂载四个接口不能替代来源平台、模型训练、评测执行或整项任务验收。

## 实施边界

1. 先逐项审计T001—T123的源任务、代码和验收条款，区分开发缺口、待验证事项和外部输入；保留全部170任务。
2. 下载只读取已登记资产的固定对象版本，校验单位、案件、来源的下载用途、分类和精确对象授权。读取完整内容并验证大小、摘要和事务末权限后才返回字节，支持已有Range契约。使用现有`max_upload_bytes`作为本批研发内存资源上限，超限明确拒绝；不把它解释为正式业务上限。
3. 来源登记使用独立权威证明端口，客户端不能声明verified。案件根权限、幂等回执、登记和审计共用事务；事务提交前重读来源证明，变化即回滚。未配置权威或权限事实适配器时拒绝。
4. 模型及评测列表按认证身份所属单位读取；根集合和逐条元数据均需授权。游标绑定身份、操作、单位、页大小及可见事实。评测对象引用通过固定只读函数核验实际登记的对象版本，不能借单位列表读取案件原件。
5. 新增0014增量迁移，仅增加固定查验函数及其最小授权；旧001—0013迁移、既有角色246格和历史注册证据保持。新接口使用严格后继注册材料记录实际差异。
6. 先运行纯单元失败证据和修复测试，再在新建隔离数据库执行SQL/HTTP/迁移回归；所有数据库测试串行。保留完整T014/T015/T016门禁和原超时，不跳过失败断言。
7. 更新任务卡中的具体子步骤、全部170项导航、接口现状和本批证据。整体未满足验收的任务继续未完成，未知责任人和审批不自动填充。
8. 在适用检查后提交现有功能分支，推送GitHub并快进同步Linux源码；核验提交对应的CI。共享数据库迁移、服务重启、main合并和正式环境验收不在本批授权内。

## 修改位置

新增下载、来源登记、模型列表服务/路由及对应测试；共享修改限于`backend/business_app`的应用装配、权限事实/集合/对象范围和固定SQL端口；数据库使用独立0014迁移。资料更新限于相关接口实现注释、权限矩阵的严格后继注册、任务证据与导航。前端仅在接口实际可用和授权边界明确后接入，不能补造业务成功。

资产页复用现有二进制业务客户端接入受控下载：仅当前已读取的VALID详情和`asset.download`权限启用；保存前核验大小、SHA-256及固定ObjectRef推导的ETag。身份、案件、资产或详情变化时丢弃旧结果。浏览器传输夹具验证和真实后端联调分别记录。

## 验收及剩余事项

每个接口均核验401/403、跨单位/案件、未知或撤销事实、固定版本绑定、错误输入、幂等或游标和最终事务权限。下载另测完整/分段/空对象/损坏/过大；来源另测pending、verified、证明失效与并发幂等；模型另测逐条范围和评测制品绑定。不开展真实训练或凭空生成评测结果。

外部真实身份交接、正式来源授权、分类规则、模型与数据、N01软件准入及T013本人密钥/恢复操作仍按原待办分别记录。不能以本批代码代替这些输入或人工决定。
