# Linux研发演示版前后端补齐实施计划

> 执行：沿用本会话已批准的工作台方案和当前会话直接实施方式；使用 executing-plans、test-driven-development，完成后独立代码复核。

**目标**：提供当前Linux/py310/CPU研发环境能够启动的前后端版本，补上真实已挂载接口的任务观察、结果及待复核入口。

**架构**：复用Vue工作台、内存业务会话、现有43项业务操作和独立业务数据库。实时执行状态与不可变结果快照分开读取。后端统一禁止缓存业务响应，保留现有权限及范围拒绝，不追加业务授权或模拟结果。

**技术**：现有Vue3、TypeScript、Vite、FastAPI及Miniforge py310；不增加依赖。

**依据**：[工作台实施计划](business-console-implementation-plan.md)、[业务启动手册](../10-deployment/business-development-runbook.md)、[API源](../03-api/openapi.yaml)、[T035](../../tasks/backend/T035.md)/[T040](../../tasks/frontend/T040.md)任务卡及既有接口实现。2026-10-21用户明确选择当前Linux研发环境可运行、可演示版本。

## 全局约束

- 原100包锁、Python环境与现有CI门禁保持；Python候选继续暂缓。
- 不修改公共端点、业务字段、数据库结构或正式授权规则，不安装或切换共享服务。
- 只调用已挂载接口；无身份/无策略仍拒绝，缺结果快照返回错误，不伪造成功。
- 凭据只存内存，不进入URL、浏览器持久存储、日志和仓库。
- 案件、对象、运行/结果版本切换不得显示旧响应；任何历史结果须核对任务和两个版本的响应头。
- 源码同步与运行采用分开记录；不得将页面完成等同170任务验收完成。

## 复核重点

1. 旧查询晚到覆盖新对象或案件：查询代际检测并先清旧数据。
2. 任务已存在但无结果：先execution，结果单独读取且不回退最新。
3. 三枚历史响应头缺失或不匹配：拒绝呈现结果。
4. 无权限、空队列、来源受阻、结果不可用：分别展示真实状态。
5. 业务响应及异常含敏感信息：统一no-store；错误不回显令牌或异常内部数据。
