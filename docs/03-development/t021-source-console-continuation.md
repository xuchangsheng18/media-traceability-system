# T021来源管理前后端续批

2026-10-21：沿用已批准的资源登记续建计划及用户继续完善前后端、同步总任务导航的授权。目标是让已有来源登记、列表和详情接口具有可操作页面，并关闭本批实际复现的来源元数据读取缺陷。原170任务、角色规则、公共契约、100包锁及CI门禁保留，Python候选继续暂缓。

## 实施范围

1. 新增`/sources`页面，使用已有`BusinessSession`、生成类型和固定业务客户端。列表和详情要求`source.read`，登记要求`source.manage`；案件来自用户选择，单位及人员仍由服务端核验。
2. 登记只发送SourceCreate既有六字段，不增加负责人、单位或客户端授权状态。RFC3339有效期保留原始精度，空值明确表示未声明截止日期；这不代替权威确认。
3. 不确定结果保留内存中的原请求和幂等键，只按原内容重试；身份、权限、案件、页面生命周期变化清空敏感结果，废弃迟到响应。不将503、pending或客户端按钮确认映射为正式授权成功。
4. 排查自然到期来源的元数据读取：只读元数据仍受单位、案件、对象及事务复核保护；到期状态应可按已有Source契约查看。上传、下载、导入和分析的有效授权要求保持。先复现失败，再作最小修复和拒绝回归。
5. 执行前端单元、类型、格式、lint、构建及浏览器流程；后端在新建隔离库串行核验登记、列表、详情、到期、跨范围和相应用途拒绝。权限代码变化另跑既有完整权限门禁及故障探针，保留原1200秒上限。
6. 更新T021及相关已有证据条目、170任务总导航、123项顺序和文档索引。按精确源码记录CI和Linux源码同步；不迁移共享库、不重启共享服务、不合并main。

## 适用限制

普通研发启动仍没有正式来源权威适配器；服务端拒绝时页面如实提示。本人责任、正式授权、到期后台告警、授权同步页面及完整任务验收仍分别保留，不因本批页面或测试通过关闭。浏览器自建传输夹具不代表真实身份/权威/数据库组合联调。

实际测试、失败与修复、源文件摘要、CI和三端同步以[本批回执](../00-project/validation/t021-source-console-report.json)为准。相关原范围见[T021任务卡](../../tasks/backend/T021.md)、[资源续建计划](t001-t123-resource-registry-continuation-plan.md)和[总任务导航](../../tasks/README.md#分步任务导航)。
