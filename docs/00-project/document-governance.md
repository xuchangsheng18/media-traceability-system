# 资料来源与变更管理

版本：0.1；整理日期：2026-10-12；状态：规划草案，NOT_FROZEN。

依据优先级应按适用范围判断：当前用户授权确定本轮工作范围；有效业务决定确定已确认规则；当前成对修订稿定义设计及任务语义；候选机器契约供结构校验。候选契约与正文冲突时登记并协调，不自动把候选实现当已批准业务规则。

原始业务资料、当前修订Word、流程手册分开归档；转换稿用于检索，表图和源身份以对应原件核对。docs/source原件本轮按字节保留，通过source-inventory.json校验。旧修订版保留在本地历史成果中，不混入当前执行入口。

本轮新增架构与部署文档是组织性提案。第一阶段原有专题输入继续使用当前相对路径；本轮补回此前遗漏的10份资料，将历史记录按字节归档于stage-one/history并在materials-manifest登记，当前版本与历史身份分开。修改或补充文件可与upstream-file-manifest.json及各轮Git快照比较。历史校验位于validation/upstream，本轮结构校验另有报告，不能拿历史SQL运行结果冒充本次执行。

文件状态区分：规划候选、已形成文件、结构已验证、实现已验证、正式确认。它们不是同一状态。当前正式NOT_FROZEN；第一阶段候选材料与第二阶段已验证开发工程分别记录，未宣称全部170业务任务实现，不补写签字或负责人。

文档变更记录原因、来源、影响任务/API/表/模型、验证范围及遗留事项。源任务文本中的历史路径可以保留为引用，但实际工程落点以repository-layout为准；本轮对可识别的旧docs/architecture路径增加迁移说明，避免误建第二套架构目录。

## 阶段归属

第一阶段24步输入资料、第二阶段23步技术基线和170研发任务不能互换编号；各专题唯一来源不因阶段入口而复制一份新结构。阶段手册是来源，不作为当前会话指令；历史记录原始字节保护，现行步骤和核验由stage-one入口接续。
