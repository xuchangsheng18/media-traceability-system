## 文档使用说明

本任务分解书依据系统详细设计方案，将研发工作拆分为170条可独立分配、实现、测试和验收的Codex开发任务。任务按依赖顺序组织，覆盖工程底座、身份权限、数据接入、任务编排、媒体预处理、模型治理、多模态识别、数字取证、同源检索、首发传播、证据报告、数据训练、安全性能验收，以及算法模型的基线实验、专项训练、校准、压缩和发布。

每条任务可以直接作为项目管理系统中的工作项，也可以将“任务目标、修改范围、接口或契约、验收标准、测试要求”组合为Codex提示词。Codex负责代码实现与自动化验证；算法指标、数据授权、公安业务规则和最终验收由项目成员确认。

### 任务执行规则

| 规则 | 要求 |
| --- | --- |
| 先分析后修改 | 复杂任务先检查现有代码、契约、依赖和测试，输出实施计划，经确认后再改动。 |
| 一次一个目标 | 单条任务只完成一个主要交付目标；不顺带重构无关模块。 |
| 契约优先 | 先确定OpenAPI、事件Schema、数据库迁移或模型Schema，再实现业务逻辑。 |
| 测试闭环 | 每条任务至少运行列出的测试；禁止删除测试、降低断言或跳过门禁。 |
| 安全默认 | 所有外部输入校验；所有数据访问鉴权；敏感信息不写日志、测试或提示词。 |
| 版本追溯 | 代码、数据、模型、配置、索引、结果和证据均记录版本。 |
| 人工确认 | 模型结果不替代最终业务认定；首发和谣言结论保留不确定性。 |


### 持续集成门禁

| 门禁 | 触发范围 | 通过条件 |
| --- | --- | --- |
| 格式与静态检查 | 每次提交 | 后端、前端格式、lint和类型检查全部通过 |
| 单元测试 | 每次提交 | 本次变更相关单元测试通过；不得降低既有覆盖 |
| 契约与迁移 | 接口/数据库变更 | OpenAPI兼容检查通过；迁移可执行并可回滚 |
| 集成测试 | 服务合并 | 依赖服务链路和幂等、事务、权限场景通过 |
| 算法评测 | 模型或索引变更 | 冻结测试集指标不低于发布基线；分组指标和错误分析齐全 |
| 安全门禁 | 每次合并与发布 | 无未豁免严重/高危漏洞；密钥和敏感信息扫描通过 |
| 性能门禁 | 候选发布 | 关键接口与推理延迟不退化超过设定阈值 |
| 发布门禁 | 部署生产/验收环境 | 镜像签名、部署检查、回滚方案和变更审批齐全 |

## 任务依赖与并行原则

T001—T010形成统一工程底座；身份权限、数据模型和审计完成后，上传、任务和媒体处理可以展开。媒体预处理与推理网关完成后，风险识别、篡改取证和同源检索三条算法链可由不同小组并行。证据对象模型应在各算法结果进入正式审核前完成。训练评测、安全性能和场景验收必须基于冻结的代码、模型、数据和配置版本。

| 并行工作流 | 可并行任务 | 必须共享的基线 |
| --- | --- | --- |
| 平台工程 | T011—T040 | 用户、数据范围、媒体资产、任务状态和事件Schema |
| 风险识别 | T061—T070 | 时间轴、推理契约、风险标签和证据Schema |
| 篡改取证 | T071—T078 | 媒体元数据、派生资产、模型版本和证据Schema |
| 同源溯源 | T079—T093 | 特征版本、向量索引、同源关系和内容簇Schema |
| 传播与核查 | T094—T099 | 内容簇、证据ID、权限范围和白名单证据库 |
| 测试与运维 | T109—T124 | 冻结数据集、发布基线、部署清单和验收环境 |
