## 文档说明

本方案将项目申报书中的研究目标、技术路线和考核指标转化为可编码、可部署、可测试、可验收的软件与算法设计。面向项目负责人、公安业务专家、算法研发人员、前后端工程师、测试与运维人员，作为需求基线、系统设计基线、迭代计划和验收实施依据。

系统定位为授权数据范围内运行的辅助核查原型，不绕过平台访问控制，不将模型结论直接作为最终执法结论。所有核心结论必须绑定原始数据、分析过程、模型版本和人工审核记录。

## 1 项目概述

### 1.1 建设背景

短视频、图片及其二次创作版本已成为网络违法有害信息和虚假叙事传播的重要载体。单一文件哈希、关键词匹配或单帧分类无法稳定处理压缩、裁剪、镜像、字幕替换、音轨替换、变速、倒放、拼接、换脸和生成式编辑。公安业务不仅要判断“有什么风险”，还要回答“是否修改、来自哪里、何时出现、如何传播、证据是什么”。

### 1.2 总体目标

建设一套可私有化部署的短视频与图片智能识别溯源原型系统，形成“内容接入—风险识别—真实性取证—同源检索—片段溯源—首发候选—传播分析—人工复核—证据固化—报告生成”的闭环，完成事故灾害类谣言核查、违法有害视听内容识别、搬运篡改内容溯源等不少于3类场景验证。

### 1.3 建设原则

| 原则 | 落实要求 |
| --- | --- |
| 合法授权 | 所有数据源登记权属、授权范围、用途和保存期限；不设计绕过访问控制的采集能力。 |
| 证据优先 | 标签、相似度和自然语言说明不是证据本身；结论必须关联帧、时间段、区域、来源和模型版本。 |
| 人机协同 | 高风险低置信、模型冲突、首发候选接近及新型篡改自动进入人工复核。 |
| 多模型协同 | 分类、检测、取证、检索、图谱、规则和大模型按任务编排协同，避免单模型作最终判断。 |
| 松耦合可替换 | 业务层只依赖能力契约，模型通过统一推理网关注册、路由、灰度和回滚。 |
| 安全可审计 | 最小权限、数据分级、操作留痕、不可变证据、离线部署和全生命周期审计。 |


## 2 范围与需求基线

### 2.1 系统范围

依法授权的公开内容、用户上传、历史材料和第三方系统数据接入。

图片和短视频预处理、多模态风险识别、篡改与深度伪造检测。

图片近重复检索、局部检索、视频片段级同源检索与多源拼接映射。

原始素材及首发候选排序、传播图谱、谣言证据核查。

任务审核、多人会审、证据固定、报告与工单、样本回流、模型运维。

### 2.2 非建设范围

不承诺对互联网全量实时覆盖，数据覆盖受授权来源与接入条件约束。

不以模型输出替代行政认定、司法鉴定或执法决定。

不实现未经授权的平台爬取、账号控制、规避验证码或访问限制。

不直接训练通用超大模型，重点进行任务适配、证据约束和可替换集成。

### 2.3 用户与角色

| 角色 | 核心权限 | 限制 |
| --- | --- | --- |
| 案件核查人员 | 创建任务、查看授权数据、提交审核意见、生成报告 | 仅访问所属单位和授权案件 |
| 业务审核员 | 复核算法证据、确认或驳回结论、发起会审 | 不可修改原始证据 |
| 数据管理员 | 数据源登记、分类分级、生命周期和脱敏策略 | 不可修改模型结论 |
| 算法管理员 | 模型注册、评测、阈值、灰度和回滚 | 原则上不可查看未脱敏案件内容 |
| 系统管理员 | 用户、角色、配置、服务和备份管理 | 业务内容访问需单独授权 |
| 审计员 | 只读查询操作、导出、模型和证据日志 | 不可执行配置变更 |


## 3 总体架构设计

图3-1 系统总体分层架构

### 3.1 架构说明

业务应用层提供任务、研判、审核和报告入口；能力服务层封装任务编排、媒体处理、检索、图谱、证据和通知能力；智能算法层通过推理网关暴露统一契约；数据资源层按对象、关系、向量、全文和证据分别存储；基础设施层提供计算、容器、消息、存储、监控和安全能力。纵向安全运维体系覆盖全部层次。

### 3.2 建议技术栈

| 领域 | 建议选型 | 设计理由 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Ant Design Vue + ECharts | 适合复杂管理端、时间轴、图谱和证据面板。 |
| 后端 | Python 3.11 + FastAPI + Pydantic + SQLAlchemy | 与AI工程栈一致，便于异步接口和类型契约。 |
| 任务编排 | Celery/自研状态机 + Kafka或RabbitMQ | 支持异步、重试、优先级、幂等和长任务。 |
| 算法服务 | PyTorch + Triton/TorchServe + ONNX Runtime | 支持GPU批处理、模型版本和多后端推理。 |
| 媒体处理 | FFmpeg + PyAV + OpenCV | 覆盖容器、编码、抽帧、音轨和时序分析。 |
| 关系数据 | PostgreSQL 16 | 事务、JSONB、审计和复杂查询成熟。 |
| 对象存储 | MinIO或兼容S3的内网对象存储 | 原始媒体、衍生文件、模型和报告统一存放。 |
| 搜索与向量 | OpenSearch + Milvus | 全文检索与千万至亿级向量检索分工清晰。 |
| 图数据库 | Neo4j或NebulaGraph | 传播关系、路径和社区分析。 |
| 缓存 | Redis | 状态、热点、锁、限流和会话。 |

### 3.3 关键设计决策

| 编号 | 决策 | 约束与结果 |
| --- | --- | --- |
| ADR-01 | 原始媒体与分析副本分离 | 原始文件只读；转码、抽帧和特征均作为派生对象并建立血缘。 |
| ADR-02 | 任务驱动而非同步长请求 | 上传后立即返回task_id；通过查询、SSE或回调获取进度。 |
| ADR-03 | 粗召回加精验证 | 向量相似只产生候选；图片经几何验证、视频经时序对齐后才能确认同源。 |
| ADR-04 | 大模型不直接定案 | 大模型用于主张抽取、证据摘要和交互解释；输出必须引用证据ID。 |
| ADR-05 | 证据事件追加写 | 分析和审核采用追加事件记录，已固化证据不覆盖，只能形成新版本。 |


## 4 业务流程与任务状态机

图4-1 在线核查主流程

### 4.1 离线建库流程

登记数据源、授权依据、采集或导入批次。

校验媒体格式并计算SHA-256，完全重复内容关联既有对象。

生成标准化副本，完成镜头切分、关键帧、音轨、OCR、ASR和元数据解析。

生成复制检测向量、语义向量、音频指纹和局部特征，并写入相应索引。

执行质量抽检、样本标注和内容簇聚合，生成可检索底库。

记录处理血缘、模型版本、失败原因和重试结果。

### 4.2 在线核查流程

用户上传文件或提交授权URL，系统完成鉴权、查毒、格式和大小校验。

创建任务并返回task_id；计算文件哈希，保存原始媒体和上传证据。

运行一级快速筛查：轻量抽帧、OCR、ASR、感知哈希、固定目标检测。

根据规则进入二级深度分析：视频时空、多模态融合、图片或视频篡改检测。

需要来源核验时进入三级溯源：多路召回、几何验证、时序对齐、首发排序和传播图分析。

生成证据卡片；自动结论按置信度与冲突规则进入人工复核。

复核通过后固化证据包、生成报告和处置工单，并将确认难例按审批流程回流。

### 4.3 任务状态机

| 状态 | 进入条件 | 允许转移 | 关键记录 |
| --- | --- | --- | --- |
| CREATED | 任务创建成功 | UPLOADING、CANCELLED | 创建人、来源、权限域 |
| UPLOADING | 分片上传开始 | VALIDATING、FAILED | 分片号、校验值、偏移 |
| VALIDATING | 文件合并完成 | QUEUED、REJECTED、FAILED | SHA-256、格式、查毒结果 |
| QUEUED | 进入调度队列 | RUNNING、CANCELLED | 优先级、队列、算法策略 |
| RUNNING | 执行分析DAG | WAIT_REVIEW、SUCCEEDED、FAILED | 节点进度、模型版本、耗时 |
| WAIT_REVIEW | 命中复核规则 | REVIEWING、CANCELLED | 触发原因、证据快照 |
| REVIEWING | 审核人领取 | SUCCEEDED、RETURNED | 意见、修改项、会审记录 |
| SUCCEEDED | 分析并确认完成 | ARCHIVED | 报告、证据清单、结论版本 |
| FAILED | 不可自动恢复失败 | QUEUED、CLOSED | 错误码、重试次数、诊断信息 |
| ARCHIVED | 到达归档条件 | — | 归档号、保存期限、完整性校验 |


## 5 功能模块详细设计

### 5.1 多源数据接入

单文件、多文件、分片和断点续传；第三方REST、消息队列和批量目录导入。

来源登记包含平台、账号、发布时间、首次发现时间、原始链接、授权依据、采集批次和页面证据。

采用upload_id管理分片；每片校验后幂等写入；合并后计算SHA-256并进行恶意文件检测。

对接适配器只实现已授权接口，不包含绕过访问控制的逻辑。

### 5.2 数据治理与资源库

建立内容、媒体版本、关键帧、文本片段、特征、同源关系、传播关系、证据和样本集统一编号。

完全重复以SHA-256判断；近重复只作为聚类候选，需经复制检测和几何或时序验证。

样本按原始素材组进行训练、验证、测试集切分，禁止不同编辑版本跨集合。

生命周期策略按原始证据、业务核查、公开素材、训练样本和临时缓存分别配置。

### 5.3 媒体智能预处理

通过ffprobe提取容器、编码、分辨率、帧率、码率、GOP、时基、音轨和字幕。

生成内部标准化分析副本，但保留原始字节、元数据和编码结构。

融合固定间隔、镜头代表帧和风险事件驱动三种抽帧策略；关键帧保留时间戳和镜头号。

OCR、ASR、音频事件、水印、EXIF和质量指标统一映射到媒体时间轴。

### 5.4 多模态风险识别

静态视觉分支完成多标签风险分类；目标检测分支定位敏感目标；时序分支识别动作和事件。

OCR、ASR、标题、正文和音频事件与视觉特征按时间轴对齐。

多模态模型输出风险类别、时间段、证据帧、触发文本和模态一致性。

业务界面同时展示模型概率、业务阈值和校准置信度，避免将概率直接解释为法律结论。

### 5.5 篡改与深度伪造检测

图片融合RGB语义、噪声残差、高频、JPEG量化表、EXIF和重采样特征。

视频空间篡改采用逐帧取证与目标跟踪；时间篡改分析光流、帧间相似、GOP、时间戳、重复帧和音频连续性。

深度伪造综合人脸纹理、时序一致性、口型语音同步与音频指纹。

输出疑似类型、区域掩码、时间点、可靠性证据和证据不足状态。

### 5.6 图片同源检索

多路召回包括SHA-256、pHash、复制检测向量、语义向量和局部特征。

支持整图、局部框选和图片检索视频关键帧。

二级使用局部匹配、RANSAC单应矩阵和内点比例验证；输出匹配区域和几何变换。

语义相似但几何不成立的候选标记为“相似非同源”，进入难负样本库。

### 5.7 视频同源与片段溯源

视频以带时间戳的关键帧向量序列表示；先按帧召回，再按来源视频聚合。

构建查询与候选帧相似度矩阵，采用DTW、Smith-Waterman式局部对齐或学习型定位模型。

输出查询片段、来源视频、来源时间段、速度比例、镜像裁剪关系和置信度。

按镜头独立检索并进行覆盖解释，支持一个查询视频映射到多个原始来源。

### 5.8 首发候选分析

同源验证通过后形成内容簇；只在内容簇内进行原始版本和首发候选排序。

特征包括平台时间、首次发现时间、完整度、画质、码率、音轨、水印、字幕、账号历史和图位置。

使用LambdaMART或其他Learning to Rank模型，并以温度缩放或等距回归校准概率。

只输出Top-3候选及支持、反对证据；证据不足时禁止生成确定性“原创”结论。

### 5.9 传播路径分析

节点包括内容、账号、平台、机构、事件、地点和话题；关系包括发布、转发、引用、同源、搬运、篡改自。

显式转发直接入图；隐式关系根据同源证据、时间方向、水印、字幕和账号互动计算概率。

展示时间线、版本差异、关键节点、传播社区和路径；每条推断边显示证据与概率。

人工可确认、驳回或调整关系，修改以新版本保存。

### 5.10 谣言证据核查

融合标题、正文、OCR和ASR抽取主体、行为、时间、地点、结果等结构化主张。

只检索纳入白名单的官方通报、权威新闻、历史辟谣和原始素材库。

证据关系分类为支持、反驳、部分支持、无关或证据不足。

大模型生成摘要时采用证据ID约束和句级引用校验；无证据句不进入正式报告。

### 5.11 审核与证据管理

支持单人复核、多人会审、退回重算、结论版本和审核意见。

证据包包含原始文件哈希、页面截图、时间、算法参数、模型版本、结果文件和操作日志。

报告生成采用结构化模板，图表和自然语言结论均可追溯到证据ID。

固化后采用只读或WORM存储；更正通过追加版本完成，不覆盖原记录。

### 5.12 综合管理与运维

角色、数据范围、接口客户端、标签、阈值、规则和通知模板统一配置。

模型注册包括模型卡、适用范围、训练集摘要、指标、依赖、镜像、版本和签名。

监控GPU、队列、接口、存储、索引、任务耗时、错误率、漂移和告警。

支持灰度、回滚、备份恢复、容量预测、审计查询和运行态势。

## 6 算法模型设计

### 6.1 分层推理策略

| 层级 | 触发范围 | 主要算法 | 目标 |
| --- | --- | --- | --- |
| 一级快速筛查 | 全部内容 | 轻量抽帧、OCR、ASR、pHash、固定目标检测、轻量分类 | 高吞吐召回与任务分流 |
| 二级深度核查 | 高风险或不确定内容 | 视频时空、多模态融合、图片/视频取证、开放词汇检测 | 提高精度并定位风险证据 |
| 三级取证溯源 | 需要来源或传播研判的任务 | 局部几何、序列对齐、首发排序、传播图和证据检索 | 形成可复核来源与传播证据 |


### 6.2 多模态风险模型

视觉编码器输出帧级特征，目标检测器输出对象及区域，视频编码器输出片段级时序特征，OCR、ASR和音频事件编码器输出带时间戳的文本与声音特征。各模态经过时间位置编码和缺失模态掩码后输入融合Transformer。模型设置多标签分类、时间边界回归、跨模态一致性和对比学习四类目标。

联合损失定义为 L = λ1Lcls + λ2Lloc + λ3Lcons + λ4Lcon，其中Lcls采用带类别权重的BCE或Focal Loss，Lloc采用边界回归与帧级二分类组合，Lcons判断文本主张与视觉事件是否一致，Lcon用于拉近同一事件多模态表示。λ可采用不确定性加权或动态权重平均，并在独立验证集上固定。

### 6.3 图片篡改模型

RGB分支侧重语义、边缘、光照和空间关系；噪声分支以SRM/高通残差或可学习噪声提取器分析相机处理链、局部压缩和重采样不一致；元数据分支编码EXIF、JPEG量化表和软件痕迹。多尺度特征经交叉注意力融合后，输出图像级概率、像素级掩码和可靠性图。对于仅有弱标签的样本，采用多实例学习；对像素标注样本使用BCE、Dice和边界损失。

### 6.4 图片同源检索

一级召回分数可按 Srecall = w1SpHash + w2Scopy + w3Ssemantic 计算，各通道独立取Top-K后按倒数排名融合。二级验证对局部关键点进行匹配，利用RANSAC估计单应矩阵H，以内点数、内点率、覆盖率和重投影误差形成几何可信度Sgeo。只有Sgeo超过分类阈值且覆盖解释合理时，候选才进入“高可信同源”。

### 6.5 视频片段对齐

对查询帧序列Q和候选帧序列C构造相似度矩阵Mij=cos(qi,cj)。正常复制在矩阵中形成正斜线，变速表现为斜率变化，倒放形成负斜线，拼接表现为多条离散高相似轨迹。局部动态规划优化累计相似度并惩罚过大跳变，输出片段边界、方向、速度比和覆盖率。边界时间由帧时间戳回映射，平均定位误差按查询与真值起止边界的绝对误差统计。

### 6.6 首发排序与概率校准

候选特征向量由时间可信度、发现延迟、内容完整度、清晰度、码率、音轨保真度、水印关系、字幕层级、账号主体、历史原创率、入度/出度和路径中心性构成。训练时以人工确认内容簇形成pairwise或listwise样本；排序模型输出分数后进行校准，并保留特征贡献。发布时间缺失、平台时间不可信或采集覆盖不足时，提高不确定性并提示人工核验。

### 6.7 综合风险分数与转人工规则

综合研判分数按风险类别分别学习，输入视觉、文本、音频、动作、篡改、同源矛盾、账号历史、传播异常和规则命中特征。系统不使用一个固定总阈值覆盖全部业务。下列任一条件触发人工复核：高风险类别置信度低于确认阈值；模型结论冲突；首发Top-1与Top-2差距过小；篡改证据可靠性不足；出现分布外样本；证据来源失效；规则指定必须复核。

## 8 接口详细设计

### 8.1 通用约定

基础路径 /api/v1；UTF-8；时间统一使用带时区ISO 8601；内部统一保存UTC。

请求头包含Authorization、X-Request-Id、X-Timestamp、X-Nonce；服务到服务调用增加签名。

大文件分片上传；分析接口异步返回202；重复提交通过Idempotency-Key实现幂等。

分页采用cursor；错误返回code、message、request_id和可安全公开的details。

所有对象ID使用不可推断的UUIDv7或同等级标识；外部接口不得暴露对象存储真实路径。

### 10.1 大模型安全边界

大模型只读取任务授权范围内的最小必要文本和结构化证据；原始媒体默认不外发。

提示模板固定系统规则，用户输入与证据内容分区标记，防止证据文本中的提示注入改变工具权限。

工具调用使用白名单和参数模式校验；模型无权直接导出、删除、发布或修改证据。

生成内容执行证据ID校验、敏感信息检查和无依据句检测；正式报告需人工确认。

记录模型、提示模板、检索结果、输出和人工修改，支持复现与审计。

### 11.2 容量估算公式

日媒体量D、平均文件大小S、原始保留天数R、派生系数α、冗余系数β时，对象存储容量约为 Cobj = D×S×R×(1+α)×β。关键帧日增量为 F = Dv×Tv×rf，其中Dv为视频日数量、Tv为平均时长、rf为每秒保留关键帧数。向量存储需计入向量维度、精度、索引开销和副本，实际以20万、200万、2000万三级压测校准。

| AT-07 | 权限隔离 | 跨单位用户访问案件任务 | 返回无权访问且记录审计事件 |
| AT-08 | 任务故障恢复 | 推理节点中断后恢复 | 从节点检查点重试，不重复写入结论 |
| AT-09 | 证据完整性 | 固化后修改对象字节 | 完整性校验失败并告警 |
| AT-10 | 无证据生成 | 大模型试图添加证据外结论 | 句级校验拦截，不进入正式报告 |

## 15 风险与应对

| 风险 | 可能影响 | 预防与应对 |
| --- | --- | --- |
| 授权数据不足 | 模型和场景覆盖不足 | 建立来源台账；合成与可控编辑增强；主动学习；分阶段冻结指标测试集 |
| 跨平台泛化不足 | 压缩和新生成器导致漏检 | 多平台多压缩测试；模型集成；难例挖掘；周期增量训练 |
| 同源误判 | 相似场景被错误关联 | 向量只做召回；强制几何或时序验证；建设难负样本 |
| 首发证据不完整 | 错误输出确定性来源 | 覆盖度提示、概率校准、Top-N证据、人工最终确认 |
| GPU资源不足 | 任务积压和延迟超标 | 分层推理、批处理、队列背压、CPU降级和容量压测 |
| 索引版本混用 | 检索结果不可复现 | 按模型版本隔离collection；版本化重建与双索引切换 |
| 大模型幻觉 | 报告出现无依据事实 | 检索证据约束、句级引用校验、规则和人工审核 |
| 证据链不完整 | 结果无法复核或验收 | 事件追加、哈希、可信时间、不可变存储和定期完整性检查 |
| 开发周期紧 | 功能广而不深 | 坚持MVP优先级；先完成3类场景和验收指标，再扩展100并发等目标 |

## 附录B 核心错误码
