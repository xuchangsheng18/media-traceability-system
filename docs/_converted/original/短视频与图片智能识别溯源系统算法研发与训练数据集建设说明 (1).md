面向网络违法有害信息治理的
短视频与图片智能识别溯源系统

算法研发与训练数据集建设说明

适用于算法任务 T125—T170

版本 V1.0  2026年9月

## 文档说明

本说明面向项目数据组、算法组、软件平台组和公安业务专家，明确多模态风险识别、图片视频篡改取证、同源检索、片段溯源、首发排序及证据核查模型所需数据。数据建设采用“公开基准数据、项目授权业务数据、可控编辑增强数据、难负样本数据、冻结独立业务测试集”五类资源协同的方式。

公开数据用于预训练、基线比较和算法验证；项目自建数据用于本地业务标签适配；增强数据用于覆盖复杂编辑和跨平台退化；难负样本用于抑制语义相似误判；独立测试集仅用于最终验收。公开数据不能替代公安业务数据，自动增强数据也不能全部计入高质量人工标注样本。

### 核心原则

| 原则 | 实施要求 |
| --- | --- |
| 合法授权 | 记录来源、许可、用途、保存期限和共享边界；不得绕过平台访问控制获取数据。 |
| 原始成组 | 原始素材及全部编辑、增强版本使用同一group_id管理。 |
| 证据可追溯 | 每条标签、关系和时间边界关联原始对象、标注人、审核人和版本。 |
| 防止泄漏 | 训练、验证、测试按原始素材组划分，不允许编辑版本跨集合。 |
| 难例优先 | 重点建设相似非同源、跨平台压缩、低清晰度和证据不足样本。 |
| 测试冻结 | 独立业务测试集只读保存，不用于调参、模型选择或难例挖掘。 |

## 2 图片与视频风险识别数据

### 2.1 图片多标签风险数据

图片风险数据用于T129—T131、T140和T141，应覆盖涉暴、血腥、涉恐、低俗、危险物品、火灾、爆炸、交通事故、安全生产事故、敏感标识、正常内容及相似易误判内容。同一图片允许同时拥有多个标签。

| 字段 | 说明 |
| --- | --- |
| asset_id | 图片唯一编号 |
| group_id | 原始素材组编号 |
| labels | 一个或多个风险标签 |
| risk_level | 业务风险等级 |
| evidence_regions | 触发证据框或区域 |
| source_id | 数据来源与授权记录 |
| quality_tags | 低清、遮挡、截图、重压缩等 |
| label_status | 待复核、已复核或存在争议 |


### 2.2 敏感目标检测数据

目标检测数据用于T132和T133，需要标注火焰、烟雾、危险物品、事故车辆、敏感标识等对象的边界框，同时记录遮挡程度、目标尺寸和困难样本状态。建议准备不少于1万张相似正常负样本，例如晚霞与火焰、云雾与烟雾、玩具与危险物品、演练现场、影视和游戏画面。

| 数据类型 | 建议数量 |
| --- | --- |
| 火焰与烟雾 | 5000～8000张 |
| 危险物品 | 5000～8000张 |
| 事故车辆及事故区域 | 4000～6000张 |
| 敏感标识 | 3000～5000张 |
| 其他专项目标 | 3000～5000张 |
| 相似正常负样本 | 不少于1万张 |


### 2.3 视频行为识别数据

视频行为数据用于T134—T136。每个重点类别建议准备1000～2000段训练片段、200～300段验证片段和200～300段测试片段。标注至少包含行为类别、起止时间、参与对象、发生区域、镜头号、清晰度、遮挡情况以及真实事件、演练、影视或游戏属性。

重点行为：打斗、追逐、跌倒、逃散、碰撞、爆炸、火灾发展、交通事故和应急处置。

负样本：正常聚集、体育活动、舞台表演、演练、影视片段和普通车辆行驶。

时间真值应以毫秒保存，并记录源视频帧率和标注容差。

### 2.4 可参考的公开视频基准

| 数据集 | 内容与用途 | 使用注意 |
| --- | --- | --- |
| UCF-Crime | 1900个长时监控视频，覆盖打斗、纵火、爆炸、道路事故、抢劫等异常事件 | 适合异常与事件基线，不能直接替代短视频平台业务数据 |
| RWF-2000 | 2000段真实监控场景暴力与非暴力视频 | 适合暴力二分类预训练和比较 |
| XD-Violence | 4754个带音频的未剪辑视频，总时长约217小时 | 适合音视频多模态暴力识别和弱监督定位 |


## 3 音频与跨模态一致性数据

### 3.1 音频事件数据

音频数据用于T137，应覆盖爆炸、撞击、呼喊、尖叫、警报、玻璃破碎、车辆碰撞、火灾环境声、普通背景声以及影视和游戏合成音效。真实现场声与后期音效必须分开标注。

| 字段 | 说明 |
| --- | --- |
| audio_id | 音频或音轨编号 |
| event_label | 音频事件类别 |
| start_ms/end_ms | 事件起止时间 |
| is_original_audio | 是否原始现场音 |

### 3.2 跨模态一致性数据

T138—T140需要由视频或图片、标题、正文、OCR、ASR和事件要素组成的成组样本，统一标注consistent、contradictory、unrelated和insufficient_evidence四类关系。重点建设旧闻新炒、异地事件、本地错误配文、演练冒充事故、重新配音、错误时间地点以及影视游戏冒充真实事件等样本。

| 样本类型 | 最低建议量 | 要求 |
| --- | --- | --- |
| 一致样本 | 5000组 | 画面与文本要素可相互支撑 |
| 矛盾样本 | 5000组 | 标明矛盾字段和两侧证据 |
| 无关样本 | 3000组 | 语义接近但事件无关联 |
| 证据不足 | 3000组 | 信息不足，禁止强制判真或判假 |

## 9 主张抽取与证据关系数据

### 9.1 主张抽取数据

T166和T167使用标题、页面正文、OCR、ASR、账号说明和转发评论构建数据，标注主体、行为、对象、时间、地点、结果、来源片段及不确定性。建议建设1万～2万条，其中无明确事实主张不少于2000条、多主张文本不少于3000条、时间地点模糊样本不少于2000条、跨模态冲突样本不少于2000条。

### 9.2 主张—证据关系数据

T168和T169需要支持、反驳、部分支持、无关和证据不足五类关系。建议建设1万～1.5万组，避免“无关”和“证据不足”比例过低。每条证据同时记录来源机构、来源类型、发布时间、采集时间、URL、页面截图、SHA-256、有效状态和覆盖的主张字段。

| 关系 | 判定标准 |
| --- | --- |
| 支持 | 证据覆盖并支持核心主张 |
| 反驳 | 证据与核心主张存在直接冲突 |
| 部分支持 | 仅支持部分要素，其他要素未覆盖或矛盾 |
| 无关 | 主题或实体相似但不能用于判断主张 |
| 证据不足 | 证据可靠但没有覆盖核心判断所需信息 |

| 首发排序 | 内容簇 | 同簇全部候选不得跨集合 |
| 主张核查 | 事件或主张组 | 同一事件不同表述尽量同组 |


推荐训练集70%、验证集15%、测试集15%。验证集用于模型选择、概率校准和阈值确定；独立业务测试集只用于阶段验收和最终验收。

### 11.1 独立测试集管理

测试集采用只读或不可变存储，并记录文件与清单哈希。

访问测试集需要专门角色或审批，所有访问进入审计日志。

训练代码和难例挖掘流程不得读取独立测试集。

每次验收固定代码提交、模型摘要、数据版本、配置和运行环境。

发现测试集污染时必须废止受影响版本并重新冻结。

## 12 数据标注与质量控制

| 环节 | 质量要求 |
| --- | --- |
| 标注规范 | 每个标签提供定义、正例、反例、边界案例和不可判定条件 |
| 预标注 | 允许模型辅助，但预标注结果必须经过人工确认 |
| 双人标注 | 高风险、篡改、同源和首发关系采用双人独立标注 |
| 冲突仲裁 | 由业务专家或高级标注员仲裁，并保存修改原因 |
| 抽样复核 | 按标注员、标签、平台和难度分层抽样 |
| 一致性检查 | 自动检查时间、区域、父子关系、标签冲突和重复样本 |
| 版本发布 | 数据集版本发布前生成统计报告、数据卡和问题清单 |


### 12.1 标注一致性指标建议

| 标注类型 | 建议指标 |
| --- | --- |
| 分类标签 | Cohen Kappa或多标注者一致率 |
| 目标框 | 标注者间IoU |
| 像素掩码 | IoU或Dice |
| 时间边界 | 起止时间平均绝对差 |
| 同源关系 | 正负关系一致率 |
| 首发候选 | Top-N候选一致率及仲裁率 |
| 主张—证据 | 关系标签Macro-F1或一致率 |


## 13 数据安全与合规

公开数据集不能默认自由使用。下载、训练和成果交付前，应逐项核查许可协议、学术或商业限制、衍生模型条款、复制保存要求、人脸与个人信息处理要求以及是否需要申请登记。

| 事项 | 要求 |
| --- | --- |
| 来源登记 | 记录网站、数据集、提供方、许可版本、申请记录和下载日期 |
| 使用范围 | 明确仅科研、内部验证或可用于交付，不得超范围使用 |
| 个人信息 | 人脸、账号、定位和其他敏感信息按最小必要原则处理 |
| 数据隔离 | 不同单位、案件和授权范围的数据逻辑或物理隔离 |
| 标注环境 | 敏感、血腥和低俗内容在受控环境标注，限制复制和外传 |
| 人员保护 | 设置内容暴露时长、轮换、心理支持和退出机制 |
| 生命周期 | 明确保留期限、归档、删除审批和删除审计 |
| 模型输出 | 不得由算法结果直接形成未经人工确认的执法结论 |
