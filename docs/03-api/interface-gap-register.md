# 接口缺口与拟补方案

53业务操作不是整体接口完整性证明。以下13项源契约实查缺口/未验证条件，**候选路径仅为评审建议，未加入OpenAPI，不可调用**。任务是建议影响范围，不自动改依赖/状态/批准。

## IF-G01 P0 上传续传与校验状态查询

现状：无读取上传进度、分片记录与VALIDATING终态的契约。

已有操作：createUpload, putUploadPart, completeUpload。建议核验任务：T022, T023, T024, T026, T027。

候选路径：GET /uploads/{id}, GET /uploads/{id}/parts。

详细拟补方案：复用UploadSession/UploadPart/UploadResult组成投影，定义已接收分片、总量/摘要、到期/校验终态，asset_id仅VALID后可分析。

关闭标准：补唯一契约/样例/映射/类型，测中断续传、重复/摘要冲突、到期和异步成功/失败。

状态OPEN；未批准；实际负责人未指定。

## IF-G02 P0 审批读取与撤销链路

已有操作：requestApproval, decideApproval, issueOperationToken。建议核验任务：T016, T102, T107, T108, T170。

候选路径：GET /approvals, GET /approvals/{id}。

详细拟补方案：复用Approval，定义有权对象列表/详情/决定历史、游标/ETag、目的/版本/到期；撤销是否走现有decisions需规则决定，不能自动赋予审批权。

关闭标准：正式规则确认后补契约/SQL映射/追踪，测跨案件、两人独立性、到期与重算使旧批准失效。

状态OPEN；未批准；实际负责人未指定。
